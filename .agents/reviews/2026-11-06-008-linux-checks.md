## Points examined

- `stdinPipe.Write` in `plugins/internal/plugin/process.go`. The `cmd.Wait`
  goroutine sets `p.err` before it closes `exited`, so the read after
  `<-exited` is ordered. `exited` does not depend on `Read` or any plugin lock:
  `cmd.Stdout` is a file, and the stderr copy writes only to `os.Stderr` and
  the tail. A failed write therefore returns once the CLI exits. A write after
  `Stop` fails with "file already closed" and returns when `Stop` kills the
  CLI, within `stopTimeout`. A write blocks for longer only if a CLI closes its
  input and keeps running, which none of the four harnesses does; `Stop` still
  ends that wait. `Close` is the embedded pipe's `Close`, unchanged.
- Claude Code's discarded first write in `plugins/claude/main.go`. `send` fails
  only on a failed write (the message is a constant map), and with the new
  writer a failed write means the CLI has exited, so `read` reports the reason,
  including a `result` line, on `ready`. The start timeout still bounds the
  wait.
- Codex's `RPCError` check in `plugins/codex/discovery.go`. `RPC.Call` returns
  an `*RPCError` only for an error response; a failed write returns the exit
  reason and a connection that ends returns `Read`'s exit reason. Only an
  answer from Codex is reported as an incompatible app-server.
- Departure: `cmd/hypercube/integration_test.go` sets `SHELL=/bin/sh`. Right.
  The test exercises panel shells, not the fallback, and should not depend on
  the runner's environment or on zsh being installed.
- Departure: `scripts/dev` uses `|| true` and `SHELL="${SHELL:-}"`. Both are
  needed under `set -euo pipefail`: without `|| true` a missing `lsof` exits
  the script, and `"$SHELL"` fails under `set -u` when unset. `terminal.go`
  treats an empty `SHELL` as unset.
- Departure: the production `/bin/zsh` fallback stays. Right for this task.
  The service sets `SHELL` (launchd today, systemd in the Linux service task)
  and `scripts/dev` now passes it, so the fallback applies only with `SHELL`
  unset; changing it belongs to the Linux service work.
