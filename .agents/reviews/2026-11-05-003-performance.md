worktree refresh, file and search routes, browser state and file polling,

- No browser rendering, frame-rate, or visual checks. Browser review covered

## F1. Opening media reads and allocates the whole file

Medium · Performance · Fixed · `internal/mcp/open_file.go:54`

An agent opening a file without line highlights caused `os.ReadFile` to load
every byte and count newlines before queuing the open request. Media previews
need neither operation. Large media therefore caused memory pressure in the
application even though preview serving streams the file separately.

### Evidence

An isolated `openFile` call on a 256 MiB sparse `.mp4`, with no line ranges,
allocated 256.02 MiB and took 32.48 ms. After the fix it allocated about 0.01 MiB
and took 0.039 ms. The experiment used `runtime.MemStats.TotalAlloc` around the
call, excluding fixture construction.

### Fix

Open and stat the file to retain readable-file and directory validation. Read
content only when ranges require line validation, counting newlines with a
32 KiB buffer rather than retaining the file. Existing path, directory,
highlight, and invalid-range tests pass.

## F2. OpenCode retains completed tool payloads

Medium · Performance · Fixed · `plugins/opencode/events.go:215`

The OpenCode plugin stored each completed tool's input, output, and images in
`ag.tools` for the life of the plugin. Subsequent updates consult only `Done`
and return, so keeping those payloads serves no purpose after emission. Memory
grew with accumulated tool results in long-running sessions.

### Evidence

Feeding 100 unique completed tools, each with a 1 MiB text result, left 100 MiB
of payload referenced by the map. The same probe after the fix retained zero
payload bytes there. This measures retained payload, not total process memory;
completion entries still retain tool IDs and their completion flag.

### Fix

Keep only a completed marker after emitting the full result. Pending tools keep
their translation state. Existing duplicate-completion and image-result tests
protect the emitted result. Active OpenCode sessions must restart after
installation to use this plugin change.

## F3. Idle refreshes run Git for archived worktrees

Medium · Performance · Fixed · `internal/session/merges.go:36`

Every idle event refreshes the workspace's merge states on the launch's reader.
Archived sessions retain their base and branch in the database, so they were
included even after archive removed their worktrees and branches. Those Git
calls add latency after each turn and serialize other refreshes through
`refreshMu`, with cost growing as archives accumulate.

### Evidence

With 20 archived worktree session records and removed branches, one isolated
refresh took 233.56 ms and produced 20 error entries. After the fix it took
0.144 ms and produced no entries. The trace reaches `MergeStatus` for each
archive, which starts Git to read the checkout branch and the removed branch.

### Fix

Exclude ended sessions before measuring their worktrees. A regression test
exercises normal session creation and idle processing, verifying that the
active worktree is measured and the archived worktree is omitted.

## F4. Startup repeats historical transcript scans

Medium · Performance · Fixed · `internal/store/migrate.go:42`

Every database open ran two JSON-based deletes across all transcript rows to
remove historical status items and mirrored requests. Current code no longer
writes those records, yet every application restart paid the scans under the
migration write transaction. Startup cost therefore grew with saved history.

### Evidence

Reopening a current-schema database with 50,000 text items of roughly 2 KiB each
took 78.31 ms. With the cleanup already recorded as applied, the same experiment
took 0.534 ms. Fixture creation and insertion were outside the timed interval.

### Fix

Record the historical cleanup in SQLite's existing `user_version` field, in
the same transaction as the deletes. Unversioned existing databases still run
the cleanup once. Per-start session attention repair remains unconditional.
Migration fixtures now identify old state explicitly, and a regression test
verifies that reopening does not repeat the historical cleanup.
