## F1. Polls drop too-large and binary messages

Medium · Correctness · Fixed · `internal/ui/static/index.html:333`

`showFile` returned on any message during a poll. A file open in a tab that
grew past 256 KiB or became binary kept its old text, with no sign that it
was stale. A file deleted while open that returned too large or binary kept
its "(deleted)" label, because the return came before the deleted state was
cleared. The plan says a tab re-renders on any response other than 304 and
that only other failures leave it as it is.

### Evidence

`files.read` returned `{message}` for 413, 415, and every other failure
alike, so `showFile` could not tell them apart and skipped all of them while
polling.

### Fix

`files.read` returns `{error}` for failures other than 404, 413, and 415.
`showFile` ignores an error during a poll and shows it on first open; 413 and
415 messages render during polls and clear the deleted state.

## F2. Tree refresh renders before the icon theme loads

Low · Correctness · Fixed · `internal/ui/static/files.js:120`

On first page load with the Files panel shown, a poll that ran before the
Seti theme arrived listed the root and rendered it, and `fileIcon` threw on
the undefined theme. The tree recovered when `reset` finished loading.

### Fix

`refresh` returns until the theme has loaded.

## F3. The repeated-message check in `showFile` never applied

Low · Simplicity · Fixed · `internal/ui/static/index.html:350`

`showFile` skipped re-rendering a message the tab already showed, but it
was called without polling only for a newly opened tab, so the check never
applied.

### Fix

The F1 fix makes polls reach this check, as the plan intends.
