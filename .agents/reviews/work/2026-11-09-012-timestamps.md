### Why the difficult parts hold

- **In-place upgrade.** `replaceInertLastActive` (`internal/store/store.go`) drops `last_active` only while the column has no default, then `addColumn` recreates it with `DEFAULT 0`. After the first open the column has a default, so the drop never repeats. No index, trigger, view or constraint names the column (`UNIQUE (parent, name)` only), so `DROP COLUMN` is valid. It runs inside Open's transaction, alongside the existing `addColumn` calls. `TestOpenAddsTipToSavedSessions` starts from `testdata/current-schema.sql` with `created = last_active = 100`, checks the row reads `LastActive == 0`, then checks `Touch(500)` survives a reopen.
- **Write paths.** `AddSession` no longer writes the column and `SaveSession` never wrote it, so read-modify-write of other fields cannot move it back (covered by `TestTouchSetsLastActiveAndSaveSessionKeepsIt`). `Touch` is the only writer.
- **What counts as activity.** Every `putItem` caller (input, finished agent items and the turn-ending idle item, error notes, offers, proposals, items drained when a session ends) is a real transcript change. Hypercube does not resave items on startup, so a restart does not bump every session. Using the current time rather than `item.At` is right for replaced items, which keep their original start time.
- **Pull requests.** `fromNode` maps a missing `updatedAt` to 0 rather than a negative Unix time. The watcher test covers both cases.
