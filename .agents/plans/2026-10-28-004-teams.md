# Teams

## Goal

A workspace holds any number of teams, and the user switches between them.
Each team is an orchestrator and the workers it creates. A new workspace
starts with one team, `default`. Ctrl-b t opens the team list, where the user
views a team, creates a team, or deletes one. The host shows the viewed
team's panes and keeps every other team's agents running in the background.
The header names the viewed team and shows which other teams have an agent
waiting for a tool approval.

## Decisions

- **Team membership.** `Agent::team: String` holds the name of the agent's
  team. `store::DEFAULT_TEAM` is `"default"`. A team is its orchestrator, the
  agent with role `orchestrator` and that team, together with the workers
  whose `team` matches. `State::teams()` returns the team names in the order
  of their orchestrators in `agents`, so `default` comes first and the other
  teams follow in creation order. `State::team_orchestrator(team)` finds a
  team's orchestrator. `prepare` sets `team` to `DEFAULT_TEAM` on every agent
  whose `team` is empty, so state files written before teams existed load
  into the default team. `State::root` uses the default team's orchestrator.
- **Names.** The default team's orchestrator stays named `orchestrator`.
  Every other team's orchestrator has the team's name, so agents can
  `send_message` it by the team's name. A new team's name passes
  `valid_name`, and it must not be `default`, an existing team's name, or an
  existing agent's name. Worker names stay unique across the workspace,
  since worktrees and branches are named after workers.
- **A new team's orchestrator.** It runs with `config.orchestrator`'s
  harness, model, and effort, in the checkout on the checkout's branch, like
  the default orchestrator. It starts idle with an empty prompt and resumes
  its saved session on every launch. Teams share the checkout. A team
  orchestrator that fails to launch gets a failed pane, as a worker does.
  Only a failure of the default orchestrator ends the session.
- **Agents and teams.**
  - `create_agent` gives the new worker the calling orchestrator's team.
  - `remove_agent` removes only workers in the caller's team.
  - `list_agents` lists the caller's team.
  - `send_message` reaches any agent in the workspace.
  - `facts` lists only the agent's own team.
  - When the workspace has other teams, an orchestrator's facts add one
    line. It says that other teams' orchestrators work in the same checkout
    and names each one with its ID. Orchestrators can then coordinate merges
    by message.
- **Background panes.**
  - `Mux::add_pane(label, background)` and `Mux::set_background(id, bool)`
    mark a pane that belongs to a team the screen does not show.
  - A background pane is never focused. `set_focus` refuses it, and
    `add_pane`'s auto-focus and `focus_from` skip it. Marking the focused
    pane background drops the focus.
  - This keeps Ctrl-b o, a melt, and an exit from moving the focus into a
    hidden team.
  - Bells and notifications from background panes still pass through.
- **Viewing a team.**
  - `Host::view: String` is the viewed team's name, and it starts as
    `DEFAULT_TEAM` on every host start.
  - `Slot` gains `team`.
  - `Host::view_team(team)` sets the view and ends any zoom. It marks every
    other team's panes background and the viewed team's panes not, focuses
    the viewed team's first live pane, and lays out.
  - `weights`, `new_weight`, and `rects` take the viewed team's slots, and
    `click` and `drag` work on those indices, so the divider and labels act
    on the visible panes.
  - `lay_out` computes `layout` (or `zoom_layout`) for the viewed team, and
    `layout` for each other team at the same size. A background team's
    programs then run at the size they will be shown at, and see no resize
    when viewed. It calls `set_layout` with all of them, then hides every
    background pane. While a full-screen view is open, it hides every pane.
  - `launch` adds a pane in its agent's team, background unless that team is
    viewed. It sizes the pane from its own team's layout and fails with
    "no room" only for that layout.
  - A team with only its orchestrator lays out as the lone orchestrator does,
    at full width with only its label row.
  - The divider split is shared by all teams.
- **Header.**
  - While the workspace has more than one team, the left text is the
    directory, then ` › ` and the viewed team's name.
  - The right text lists each other team that has an agent waiting for a
    tool approval, as `<team> <bell>`. The default team comes first, the rest
    follow in creation order, and entries are joined by ` · `. Each bell is
    `icons::ATTENTION` in `colors::ATTENTION`.
  - `read_bar` reads the teams and their attention flags from the state it
    already loads every second. It refreshes the branch detail of every
    team's orchestrator, not only the first slot's.
  - The bar's attention bell after a workspace's tab already counts every
    agent, so it needs no change.
- **Team list.**
  - Ctrl-b t (`Prefixed::Teams`, `Notice::Teams`) opens or closes it. It
    toggles capture as Ctrl-b s does.
  - It is a full-screen view in the overlay's style, `teamlist::TeamList`,
    with a title row ` Teams` and one row per team in `State::teams()`
    order.
  - Each row starts with the team's state icon in its state color: running
    while any of its agents is busy (`icons::RUNNING`, `colors::RUNNING`),
    failed while its orchestrator is `EXITED` (`icons::FAILED`,
    `colors::ERROR`), and idle otherwise (`icons::IDLE`, `colors::QUIET`).
    The name follows, bold for the viewed team, then its agent count.
  - A row ends with an `icons::ATTENTION` bell in `colors::ATTENTION` while
    one of the team's agents waits for a tool approval.
  - The selected row is drawn in `Palette::selected`. It opens with the
    viewed team selected.
  - Keys: Up/Down or k/j move. Enter views the selected team and closes the
    list. n starts a name prompt in the last row (` New team: <name>`), and
    while it is open, typed characters build the name, Backspace deletes,
    Enter creates, and Esc cancels. x deletes the selected team. Esc or
    Ctrl-b t closes the list.
  - The last row shows ` ↑↓ move  enter view  n new  x delete  esc close`,
    or the name prompt, or an error until the next key.
  - It is read again every second while open.
  - The team list, the workspace overlay, the list of keys, and the
    workspace prompt each close the others.
- **Creating a team** happens in the host. `Host::create_team(name)`
  validates the name and, in one update, adds the orchestrator with `team`
  set to the name. It launches it with an empty prompt, then views the new
  team. When the launch fails, it removes the agent and shows the error in
  the list.
- **Deleting a team.**
  - `Host::delete_team(name)` refuses the default team, and refuses a team
    that has workers, naming them.
  - Otherwise it closes the orchestrator's pane and, in one update, checks
    again for workers, since the orchestrator may have created one
    meanwhile. If there are any, it keeps the orchestrator and reports that
    the pane was closed and the workers must be removed first. Otherwise it
    removes the agent and its queued messages.
  - Deleting the viewed team views the default team.
  - The orchestrator's harness session stays where the harness keeps it.

## Test plan

- `store`: a state without `team` loads; `teams` orders the default team
  first and the rest by creation; `team_orchestrator` and `root` find the
  default team's orchestrator when other teams exist.
- `host::prepare`: agents without a team join the default team; the first
  start creates the orchestrator in `default`.
- `mux`: a background pane is not focused by `add_pane`, `focus_next`, or
  `release_focus`; `set_background` on the focused pane drops the focus.
- `host` layout: `lay_out` gives a background team's panes the layout their
  team would have at the same size, then hides them; the viewed team's
  single orchestrator fills the width.
- `host` chrome: with one team, the header shows only the directory; with
  several, it shows ` › <team>`; the right text lists other teams waiting for
  an approval with bells, never the viewed team.
- `teamlist`: keys move, view, start, edit, cancel, and submit the name
  prompt, delete, and close; the initial selection is the viewed team;
  drawing shows each row's state icon in its color, the bold viewed team,
  the agent counts, the bell, the prompt, and an error.
- `host` teams: `create_team` rejects an invalid name, `default`, a taken
  team name, and a taken agent name, changing nothing; `delete_team` refuses
  the default team and a team with workers, keeps the orchestrator when a
  worker appears between its check and its update, and otherwise removes
  the agent and its messages.
- `mcp`: a worker created by a team's orchestrator joins that team;
  `list_agents` lists the caller's team; an orchestrator cannot remove
  another team's worker.
- `hook`: `facts` lists only the agent's team, and an orchestrator's facts
  name the other teams' orchestrators when there are any.
- Integration: Ctrl-b t opens the list showing `default`; n, a name, and
  Enter create a team whose orchestrator's pane is shown alone, and the
  header shows ` › <name>`; its stand-in's `create_agent` adds a worker shown
  only in that team's view; Ctrl-b t, selecting `default`, and Enter return
  to the default team's panes; a stand-in's permission request in the
  hidden team shows its name and a bell in the header; after the worker is
  removed, x on the team deletes it.

## Implementation plan

1. `src/store.rs`: add `Agent::team`, `DEFAULT_TEAM`, `State::teams`, and
   `State::team_orchestrator`; make `State::root` use the default team's
   orchestrator.
2. `src/host.rs` `prepare`: fill empty teams, and create the first
   orchestrator in `DEFAULT_TEAM`.
3. `src/mux.rs`: the `background` argument of `add_pane`, `set_background`,
   and the focus rules; `Prefixed::Teams` on `t` and `Notice::Teams`, which
   toggles capture.
4. `src/icons.rs`: `IDLE` (nf-fa-pause).
5. `src/teamlist.rs` (new): `TeamList` with `load`, `reload`, `key`, and
   `draw`, and its `Action` (`None`, `Move`, `View`, `Create`, `Delete`,
   `Close`), drawing rows the way the overlay does. Declare it in
   `src/lib.rs`.
6. `src/host.rs`:
   - Add `Slot::team` and `Host::view`.
   - Make `start`, `launch`, `add_failed`, `weights`, `new_weight`, `rects`,
     `click`, `drag`, `lay_out`, `place`, and `finish_close` team-aware.
   - Add `view_team`, `create_team`, and `delete_team`.
   - Add the team list's toggle, keys, and refresh in `serve`, and its place
     among the full-screen views in `close_screens`, `toggle_overlay`,
     `toggle_help`, `open_prompt`, and `attach`.
   - Make `read_bar` refresh every orchestrator's branch detail and the
     teams' attention.
   - Draw the header's team name and waiting teams in `TeamChrome::draw`,
     and the team list over the screen while it is open.
7. `src/mcp.rs`: teams in `create_agent`, `remove_agent`, and `list_agents`.
8. `src/hook.rs`: `facts` lists the agent's team, and the other teams'
   orchestrators for an orchestrator.
9. `src/help.rs`: add `Ctrl-b t`.
10. `tests/integration.rs`: the teams test above.
