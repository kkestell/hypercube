## Outcome and boundaries

The user asked for missing timestamps, then narrowed the scope: "Just add the
timestamps and start logging them and we'll add them to the UI later." This
task records two times in the backend:

- Session last activity in `sessions.last_active`, which today holds the
  creation time and never changes. Existing databases upgrade in place, and
  rows written before the change read 0 (no real time).
- Each pull request's GitHub `updatedAt`, on the Go `PullRequest`.

Out of scope: every interface change, the snapshot sent to the page
(`internal/ui/snapshot.go`), and browser types. Transcript item times need no
work: each item already records `harness.Item.At` (JSON `at`) when Hypercube
first receives it.

## Current system

- `internal/store/store.go`: `last_active INTEGER NOT NULL` has no default.
  `AddSession` writes `created` into it; nothing reads or updates it. `Open`
  runs the schema, then `addColumn` for `tip` and `archived`.
  `testdata/current-schema.sql` is the installed baseline, with `last_active`
  lacking a default.
- `internal/session/feed.go` `write.putItem` saves every finished transcript
  item inside `Runtime.save`'s transaction. Its callers cover input reaching the
  agent (`commands.go`), finished agent items and the idle state item that ends
  a turn (`event.go`), host notes (`launch.go`, `deliver.go`), offers
  (`offers.go`), and proposals (`proposals.go`). `checkpoint` in `event.go`
  saves unfinished streaming items with `PutEntry` directly.
- `internal/github/pulls.go`: the `pr` fragment of `pullRequestsQuery` reads
  comment and commit times, not `updatedAt`. `fromNode` builds `PullRequest`
  (`internal/github/watcher.go`).

## Chosen design and decisions

### Session activity

- **What counts:** saving a transcript item through `write.putItem`, whether
  the item is new or replaces an earlier one (an answered offer or a reopened
  proposal is user activity). `checkpoint` and unsaved streaming updates do not
  count; the idle item saved at the end of each turn moves the time forward.
- **Value:** the current time in Unix ms, not `item.At`, because a completed
  long item keeps its start time while the activity happened now.
- **Store API:** `func (t *Tx) Touch(session string, at int64) error` runs
  `UPDATE sessions SET last_active = ? WHERE id = ?`. `store.Session` gains
  `LastActive int64` with a doc comment: when the session's transcript last
  changed, in Unix ms; zero before that and for activity before it was
  recorded. Read it in `sessionColumns` and `scanSession`. `SaveSession` does
  not write it, so read-modify-write of other fields never moves it back.
  `AddSession` stops writing `last_active` and relies on the column default.
- **Runtime:** in `write.putItem`, after `PutEntry` succeeds, call
  `w.Touch(id, time.Now().UnixMilli())`.

### In-place upgrade

Existing `last_active` values equal `created` and are not activity. In `Open`,
after the `archived` column, call a new `Tx.replaceInertLastActive`:

1. `SELECT dflt_value IS NULL FROM pragma_table_info('sessions') WHERE name = 'last_active'`.
2. When it returns true, `ALTER TABLE sessions DROP COLUMN last_active`.
3. `addColumn("last_active", "INTEGER NOT NULL DEFAULT 0")`; this also covers a
   database without the column.

The schema's definition becomes `last_active INTEGER NOT NULL DEFAULT 0`, and
the "inert field" comment goes. New databases have the default, so the drop
runs only once, and every pre-change row reads 0. `DROP COLUMN` needs SQLite
3.35; `modernc.org/sqlite` v1.61.1 bundles a newer one, and the column has no
index or constraint. Rejected alternatives: zeroing rows where
`last_active = created` on every start (a guess that runs forever), and a new
`user_version` mechanism (new machinery for one migration).

### Pull request update time

Add `updatedAt` to the `pr` fragment, `UpdatedAt time.Time json:"updatedAt"` to
`pullRequestNode`, and `Updated int64 json:"updated"` to `github.PullRequest`
(Unix ms of GitHub's last change to the pull request; 0 when unknown). In
`fromNode`: `if !n.UpdatedAt.IsZero() { pr.Updated = n.UpdatedAt.UnixMilli() }`,
so a node without the field gives 0 rather than a negative value. The field
reaches the page inside the existing GitHub status JSON; the browser ignores it
until the interface work. Pull requests are not saved, so no migration.

## Implementation sequence

1. Store: schema default, `replaceInertLastActive` in `Open` and its doc

   `last_active`.
2. Runtime: `Touch` in `write.putItem`.
3. GitHub: query field, node field, `PullRequest.Updated`, `fromNode`.
