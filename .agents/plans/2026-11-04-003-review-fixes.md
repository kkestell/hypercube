# Fix the entire-codebase review findings

## Goal

Fix F1–F11 in `agents/reviews/2026-11-04-003-entire-codebase.md`, preserving
the existing behavior outside the confirmed failures.

## Decisions

The baseline is to repair the current paths: runtime lifecycle locking and
deletion flags, the existing migration transaction, literal Git filenames,
Codex request routing and shared-input links, and the existing React highlight
and overlay effects. Each change addresses a reviewed failure; none requires
a new subsystem or a new public interface. Split lifecycle cleanup out of
`sessions.go` if needed to keep the resulting files easy to follow.

Keep ordinary dirty-worktree refusals non-destructive. Once cleanup passes its
initial checks, stop the relevant writers and check again before removing
files. Synchronize child membership and terminal admission with those same
lifecycle decisions. Never hold the runtime lock while waiting for a plugin.

Keep resumed Codex conversations on their original account. Reconcile missing
shared-input links using that source, even if a different account is currently
selected. Preserve literal code and raw HTML behavior when decoding Markdown
entities, and validate decoded link destinations.

Fixes remain unstaged and uncommitted. Plugin fixes require active sessions to
restart after installation; the installed app is outside this task.

## Implementation plan

1. Fix F1, F2, and F11 in `internal/session/` and, only if necessary,
   `internal/terminal/`. Cover concurrent child creation during cleanup,
   writes made before a child stops, and terminal admission during stop/end.
2. Fix F3 in `internal/store/migrate.go`: restore upgrades from the previously
   supported saved schemas within the existing transaction. Restore focused
   prior-schema fixtures and preservation checks.
3. Fix F6 in `internal/workspace/workspace.go`: carry Git filenames with NUL
   delimiters through inclusion filtering and copy literal paths. Cover
   Unicode and quoted/newline filename cases through worktree creation.
4. Fix F4, F5, and F7 in `plugins/codex/`: route async answers to their native
   thread, reject nonfinite numbers and fractional integers before closing a
   field, and expose newly created shared inputs on resume without changing
   account selection. Extend the existing stand-in and storage tests.
5. Fix F8, F9, and F10 in `internal/ui/web/`: decode Markdown entities, give
   the active Find ownership of its highlight, and register Profile/View
   dropdowns with `useOverlay`. Add focused behavior regressions and regenerate
   browser assets through the build.
6. Have agents review implementation areas they did not write, verify their
   findings, resolve defects within these approved fixes, and update the
   original review with the resulting corrections and verification.

## Test plan

Use deterministic condition/barrier tests for the cleanup races, saved-schema
upgrade tests that preserve sessions/messages/transcripts, and focused plugin
and frontend regression tests for the reproduced failures. Run the repository
checks once the combined implementation is ready. Reuse the existing dev server
for the browser smoke test and open it for the user's visual assessment.
