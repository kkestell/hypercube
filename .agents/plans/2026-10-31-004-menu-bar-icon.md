# Show the view in the menu bar

Builds on `2026-10-31-003-ui-service.md`.

## Goal

The user can open the browser view, and see that it is serving, from a macOS
menu bar icon. The icon lives in the `hypercube ui` process, so it is present
exactly while the view serves. The login service starts it with `--menu`;
manual runs and `make dev` do not.

## Related code

- `cmd/hypercube/main.go` — `usage` lists the commands; `main` dispatches `ui`;
  `serveUI` parses the port and blocks in `http.ListenAndServe`.
- `internal/ui/ui.go` — `Handler` builds the view's routes.
- `scripts/install-service` — writes the property list whose `ProgramArguments`
  run `exec "$BINDIR/hypercube" ui $PORT`.
- `Makefile` — `install-service` writes the property list; `reinstall-ui` only
  kickstarts the loaded service and does not rewrite it.
- `cmd/hypercube/main_test.go` — command-level tests.
- `docs/usage.md`, `docs/installation.md` — the `ui` row and the service
  description.

## Decisions

- **Process:** the status item runs inside `hypercube ui`, not in a second
  launchd agent. The icon is present exactly when the view is serving, so there
  is no polling, no port probe, and no way for the icon to claim a state the
  server is not in. A separate agent could show a stopped state and restart the
  view, but `KeepAlive` already restarts the view within a second, so that adds
  a second lifecycle without a useful signal.
- **No Quit:** the service owns the process and `KeepAlive` restarts it at once,
  so a Quit item would be undone before the menu closed. Stopping the view
  remains `launchctl bootout`, which `docs/installation.md` already documents.
  The menu has a disabled status row, `Open Hypercube`, and a separator.
- **Library:** `fyne.io/systray` v1.12.2. It is maintained, its macOS backend
  creates an `NSStatusItem`, and `SetTemplateIcon` marks the image as a template
  so it follows the menu bar's light and dark appearance. It needs cgo; the
  project targets macOS and builds with the default `CGO_ENABLED=1`.
- **Threading:** systray's macOS `Run` calls `[NSApp run]` on the goroutine that
  calls it, so `main` calls `runtime.LockOSThread()` first and `serveUI` calls
  `menu.Run` on the main goroutine. The HTTP server runs in another goroutine.
  Locking the thread affects only the main goroutine.
- **Startup order:** with `--menu`, `serveUI` calls `net.Listen` before showing
  the icon, so a port already in use fails before anything appears and with the
  same message as today. It then serves `ui.Handler()` in a goroutine. If
  serving fails, it prints the error to the log, quits the status item, and
  returns so launchd restarts the process.
- **Flag:** `hypercube ui [port] [--menu]`, parsed by hand in `serveUI` like the
  rest of `main`. At most one port argument; `--menu` may come before or after
  it; anything else is an error. Only `scripts/install-service` passes `--menu`,
  so `make dev` on port 4281 and a manual `hypercube ui` stay as they are.
- **Dock icon:** `internal/menu` sets
  `NSApplicationActivationPolicyAccessory` before the run loop starts, through a
  small cgo file. The service then has no Dock icon and does not enter the app
  switcher, without shipping a `.app` bundle and a second copy of the binary.
- **Icon:** `internal/menu/icon.png`, a 44×44 black-on-transparent drawing
  embedded with `//go:embed`. systray loads it as an `NSImage`, sets it to 16×16
  points, and marks it a template. The same bytes are passed as the template and
  regular image because the project is macOS-only.
- **Package:** `internal/menu` exposes `Run(url string)` and owns the systray
  dependency, the icon, and the accessory-policy call. `cmd/hypercube` stays a
  plain caller.

## Test plan

- `TestParseUIArgs`: `{}` returns 4280, false; `{"5000"}` returns 5000, false;
  `{"--menu"}` returns 4280, true; `{"5000", "--menu"}` and
  `{"--menu", "5000"}` return 5000, true. Errors for `{"0"}`, `{"70000"}`,
  `{"abc"}`, `{"5000", "6000"}`, and `{"--bogus"}`.
- `make check` passes. It now needs cgo to build `cmd/hypercube`.
- Live, run by the user:
  - `make install-service` once rewrites the property list with `--menu`. A
    template icon appears, no Dock icon appears, and the menu shows
    `Serving on localhost:4280` and `Open Hypercube`, which opens the view.
  - `launchctl kickstart -k gui/$(id -u)/com.github.kkestell.hypercube` removes
    the icon and brings it back when the new process listens.
  - `launchctl bootout gui/$(id -u)/com.github.kkestell.hypercube` removes the
    icon.
  - `bin/hypercube ui 4281` and `make dev` show no icon.
  - With another process holding port 4280, a restart shows no icon and the log
    ends with the same `address already in use` error as today.
  - The icon is legible in light and dark menu bars.

## Implementation plan

1. `go get fyne.io/systray@v1.12.2`.
2. `internal/menu/menu.go` (new): embed `icon.png`; `Run` sets the template
   icon, adds the disabled status row, `Open Hypercube`, and the separator, then
   calls `systray.Run`. The click handler runs `open` in a goroutine and prints a
   failure to stderr.
3. `internal/menu/accessory.go` and `internal/menu/accessory.m` (new): set the
   accessory activation policy, called from `Run` before `systray.Run`.
4. `internal/menu/icon.png` (new): 44×44 black-on-transparent mark. Replacing
   the file changes the icon without code changes.
5. `cmd/hypercube/main.go`: call `runtime.LockOSThread()` at the top of `main`;
   allow `ui` with up to two arguments; replace `serveUI` with `parseUIArgs`
   plus the listen, serve, and menu branch, leaving the no-menu path as
   `http.ListenAndServe`; update `usage`.
6. `scripts/install-service`: run `exec "$BINDIR/hypercube" ui --menu $PORT` in
   the property list.
7. `cmd/hypercube/main_test.go`: add `TestParseUIArgs`.

- `docs/installation.md`: the service paragraph says the icon is in the menu bar
