# Make the browser view the only interface

## Goal

Hypercube is used only through the browser view. The terminal client goes
away: no attaching, no tmux status lines, pane titles, or key bindings. tmux
stays as the owner of agent processes, and the browser view stays a tmux
control-mode client. The command line keeps the lifecycle commands that the
browser view, `scripts/reinstall`, and `scripts/dev` use.

## Related code

- `cmd/hypercube/main.go` — `main` dispatches commands; `start`,
  `startWorkspace`, `newSessionArgs`, and `openWorkspace` attach and select
  windows; `windowAction` serves the browser view's session actions and the
  tmux key bindings; the `window` case shows errors with `display-message`.
- `internal/tmux/tmux.go` — `NewPane` sets terminal-only window options;
  `ConfigureSession` sets the status lines, mouse, key bindings, and the hooks
  that clear `@hypercube_replied`; `Activity` writes `@hypercube_activity` for
  the pane title; `attention` builds the status-line dots; `Attach` attaches.
- `internal/ui/static/index.html` — `resizeTerminals` and `desired` count the
  pane title row that `pane-border-status top` adds.
- `internal/ui/ui.go` — `Handler`; `cmd/hypercube/main.go` listens on the fixed
  address `127.0.0.1:4280`.
- `cmd/hypercube/integration_test.go` — `TestTmuxNativeLifecycle` uses
  `hypercube new -d`, `delete-session`, and prefix keys through an attached
  client.
- `scripts/dev` — opens Ghostty attached to the dev workspace.

## Decisions

- **Commands that stay:** `start <dir>`, `stop`, `delete`, `status`, `running`,
  `ui`, and the internal `window`, `agent`, `exited`, `mcp`, `report`, and
  `wait`. `hypercube` with no arguments prints the usage message. `new` and
  `delete-session` are removed; the browser view creates and deletes sessions
  through `window new` and `window delete`.
- **`hypercube ui [port]`:** an optional port, default 4280, so the dev session
  can serve its own view beside the user's. It still listens only on
  127.0.0.1.
- **tmux options that stay:** `remain-on-exit`, the `pane-died` hook,
  `main-pane-width` and `main-vertical` (the view's divider and new-worker
  layout use them), `automatic-rename off` and `allow-rename off` (window names
  are session titles in the sidebar), `extended-keys always` (harnesses read
  modified keys through it), the `@hypercube_*` markers, `@hypercube_workspace`,
  and the `session-window-changed` and `client-session-changed` hooks, which
  clear a session's unseen reply when the view switches to it.
- **tmux options that go:** `pane-border-status`, `pane-border-format`,
  `window-status-format`, `window-status-current-format`,
  `window-status-separator`, `mouse`, `status-style`, `status-left`,
  `status-right`, `status`, `status-format[0]`, `status-format[1]`,
  `@hypercube_exe`, and the `c`, `W`, and `X` bindings.
- **Pane rows:** without the title row, every pane's terminal is its full tmux
  height. Stacked panes are still separated by one border row.
- **Dev session environment:** the dev workspace and its view start under
  `env -i` with only `HOME`, `USER`, `PATH`, `LANG`, `TERM`, and the dev
  variables, which the Ghostty launch gave it before. Agents launched by the
  dev view must not inherit the environment of the agent that ran
  `scripts/dev`.

## Test plan

- `TestTmuxNativeLifecycle` creates its second session with
  `hypercube window new <state>` and deletes sessions with
  `hypercube window delete <state> <team> <window>`, including the refused
  deletion of a dirty worktree and the deletion of the final session, whose
  cleanup must finish as tmux exits. The prefix-key steps and `attachClient`
  go away.
- `TestTmuxNativeLifecycle` checks that a workspace's session has none of the
  removed options set (`show-options -t =<session>: status` reports the
  default) and that a team window has no `pane-border-status`.
- `hypercube` with no arguments exits with the usage message.
- `TestActionsRejectBadRequests` and `TestPageDrivesControlClient` still pass.
- Live: `make dev` opens the dev view in the browser; the lead fills the
  window's height with no blank or cut-off row; adding a worker and opening its
  card sizes both terminals to their panels; dragging the divider still works.

## Implementation plan

1. `internal/tmux/tmux.go`: remove the terminal-only options from `NewPane`.
   Reduce `ConfigureSession` to setting `@hypercube_workspace` and the two
   hooks. Remove `@hypercube_activity` from `Activity` along with the text it
   builds. Remove `attention` and `Attach`.
2. `cmd/hypercube/main.go`: remove `start`, `newSessionArgs`, and the no-argument
   and `new` and `delete-session` cases; no arguments prints the usage message.
   Change `openWorkspace(dir, title string, create, selectNew, attach bool)` to
   `openWorkspace(dir string, create bool)`: a created session is always
   selected and its title is the first unused `Session N`. Update
   `startWorkspace` and `windowAction`. Remove the `display-message` on
   `window` errors and let the `window` case accept only its exact argument
   counts. Parse the optional port for `ui`. Update the usage string.
3. `internal/ui/static/index.html`: drop the title row. In `resizeTerminals`,
   a pane's rows are its layout height. In `desired`, `rows` loses its `+ 1`,
   the first stacked cell loses `(i ? 0 : 1)`, and `free` becomes
   `rows - (n - 1)`, since only the borders between stacked panes take rows.
   Update the comments that describe the title row.
4. `cmd/hypercube/integration_test.go`: apply the test plan.
5. `scripts/dev`: `up` builds, stops, prepares the repository and
   configuration as now, then starts the workspace with `dev start "$REPO"` and
   the view with `dev ui 4281` in the background, saving its process ID in
   `$DEV/ui.pid` and its output in `$DEV/ui.log`, and opens
   `http://localhost:4281/`. `stop` also ends the saved view process. `dev()`
   runs under `env -i` as decided above. Remove the Ghostty run file.

## Documentation updates

- `docs/usage.md`: start from the browser view or `hypercube start <dir>`;
  remove `hypercube`, `hypercube new`, and `delete-session` from the command
  table and add the `ui` port; remove the Keyboard controls section; describe
  the browser view as the interface rather than a second view of the terminal;
  rewrite Resume and cleanup without attaching.
- `docs/installation.md`: Upgrades no longer says to attach afterward;
  Development describes the dev view in the browser instead of Ghostty.
- `docs/architecture.md`: the tmux row lists panes, windows, and titles,
  without bindings.
- `README.md`: the Usage entry drops keyboard controls.
- `AGENTS.md`: the `scripts/dev` description still holds; no change.
