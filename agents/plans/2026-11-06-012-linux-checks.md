# Linux checks in CI and a passing test suite

## Goal

GitHub Actions runs `make check` on `ubuntu-24.04` and `ubuntu-24.04-arm` as
well as `macos-15`, and the whole check passes on all three. This is the first
task in `agents/todo.md`'s Linux list; the findings are in
`agents/research/linux.md`.

`make check` was run in an ARM64 `golang:1.27.3` Debian container (non-root
user, `docker run --init`, Bun 1.4.2) with every change below applied as a
prototype, and passed. Without the changes it fails in six places:

| Failure | Cause | Fix |
| --- | --- | --- |
| `internal/workspace` worktree tests, every run | `cp -c -R`; GNU `cp` has no `-c` | Platform clone flag |
| `TestStartReportsAProcessThatEnds` (Codex, Pi), `TestStartFailedResume` (Claude Code), 16 of 120 runs | The plugin writes to a CLI that already exited and reports the write error | `plugin.Process` reports the exit reason for a failed write |
| `internal/session` `TestTranscriptKeepsOrderAndReplacesItems`, intermittent | The test's wait condition reads two values at different times | Wait on the finished item |
| `internal/hold` `TestTerminalResizeHangupAndRetention`, 20 of 20 runs | Debian's `/bin/sh` (dash) makes a bare `exit` in a trap return the killed `sleep`'s 129 | `exit 0` in the test's trap |
| `desktop/setup.test.js` launchd plist test | The installer and the test run macOS's `plutil` | Run the launchd tests on macOS only |

`make check`'s other steps run on Linux unchanged: the UI build, the Hugo
`web-build` (the cgo build of Hugo extended needs a C compiler, which the
Ubuntu runners have), `tsc` and the UI tests, and the desktop Bun install with
`ELECTRON_SKIP_BINARY_DOWNLOAD`.

`scripts/dev` also gets two fixes so `make dev` works on Linux: it passes
`SHELL` to the backend, and its port-in-use message no longer needs `lsof`.

## Related code

- `.github/workflows/check.yml` — the one `check` job on `macos-15`.
  `release.yml` calls it with `needs: check`, so beta releases also wait for

  name the job.

  "incompatible Codex app-server; update Codex".

## Decisions

### CI matrix

Turn the `check` job into a matrix over `macos-15`, `ubuntu-24.04`, and
`ubuntu-24.04-arm` with `fail-fast: false`, so one platform's failure still
shows the others' results. The steps stay the same; `setup-go` and
`setup-bun` support all three runners.

### Worktree include copies

Run `cp -R <clone flag>`: `-c` on macOS, `--reflink=auto` on Linux, chosen with
`runtime.GOOS` in a small function next to `copyIncluded`. `--reflink=auto`
clones on Btrfs and XFS and copies elsewhere. GNU `cp -R` copies symlinks as
symlinks and keeps file modes (checked in the container with coreutils 9.7;
Ubuntu 24.04 has 9.4). The comment and `docs/configuration.md` describe the
copies as copy-on-write clones where the file system supports them (APFS on
macOS, Btrfs and XFS on Linux), otherwise ordinary copies.

### A harness that exits before the plugin's write

The plugin starts the CLI and writes its first request at once. A CLI that
exits immediately makes that write fail in one of two ways, both observed on
Linux:

- before `cmd.Wait` returns: `write |1: broken pipe`;
- after `cmd.Wait` returns, because `Wait` closes the stdin pipe:
  `write |1: file already closed`.

The plugin reports that write error instead of the CLI's exit status and
stderr. `plugin.Process` already owns the pipes and the exit reason, so it owns
the fix: `Process.Stdin` becomes a small writer around the stdin pipe whose
`Write`, on any error, waits until the CLI has exited and returns the exit
reason (`<name> exited: exit status N: <stderr tail>`). A write to a pipe
fails only when the CLI has closed its input or exited, or after `Stop` closed
it; in every case the CLI is ending, and `Stop` kills it within
`stopTimeout`. The wait does not depend on the output reader: the goroutine
that runs `cmd.Wait` closes `exited`. This fixes Codex, Pi, and OpenCode
through their existing writes, with no change to `plugin.RPC`.

Claude Code needs one more change. Its start fails with the reason in a
`result` line on stdout (a conversation that cannot be resumed), which only
`read` sees; the exit reason from the write holds only stderr. With the
`Process` change alone, `TestStartFailedResume` failed 3 of 100 runs in the
container with "claude is not running: claude exited: exit status 1: resume
failed". So `initialize` does not return the `send` error: if the write fails,
the CLI has exited, and `read` reports why on `ready`. The prototype discards
the `send` result with `_ =` and a comment saying so.

Codex's `initialize` then reports the exit reason, but still under
"incompatible Codex app-server; update Codex", which is wrong when Codex
exited. Wrap only an `*plugin.RPCError` (Codex answered `initialize` with an
error) and return other errors as they are.

Prototype results in the container: 300 runs of the three tests with no
failures; all plugin packages pass three runs under `-race`; macOS passes 20
runs.

### `TestTranscriptKeepsOrderAndReplacesItems`

The code is right and the test waits on the wrong condition. `saveEvent`
saves an event's finished items and the session's activity in one
transaction, so the idle state and the final text item are never stored
apart. The test's condition reads the stored session and then the transcript
in two separate reads. `Input` returns when the plugin accepts the input,
before the turn's `Working` event is applied, so the session read can still
see the previous turn's idle state while the transcript read, a moment later,
sees the streamed "Hello" item and the tool item: 8 items, the condition
holds, and the assertions fail. Adding delays to the stand-in and between the
two reads reproduced the exact failure in 3 of 3 runs.

Wait instead on the transcript alone: 8 items and `items[6].Done`. The final
text item is applied and saved under `mu` together with the idle state, so a
finished item means the turn ended. With the same delays, this passed 3 of 3
runs. The test does not assert anything about the idle state, so the
`store.Idle` check goes; drop the `store` import if nothing else uses it.

### `TestTerminalResizeHangupAndRetention`

The holder stops a terminal child by sending SIGHUP to its process group.
`sleep` dies from the signal (status 129), the shell then runs its trap, and a
bare `exit` in a trap exits with the status from before the trap. Dash, the
`/bin/sh` on Debian and Ubuntu, does this, so the test sees exit 129 every
time. macOS's `/bin/sh` exits 0. The test asserts a clean exit after the
shell handles the hangup, so the script should say so: `trap 'echo hungup;
exit 0' HUP`. Passed 20 of 20 runs on Linux and 3 of 3 on macOS. The findings
recorded `internal/hold` as passing; this run failed every time.

### The launchd installer tests

`scripts/install-service` writes a launchd plist and validates it with
`plutil`, and the "login service" test reads the plist with `plutil`. Both
tests that run the real installer through `isolatedInstaller` test the macOS
service, so run them only on macOS with `test.if(process.platform ===
'darwin')`, defined once next to `isolatedInstaller` with a comment naming the
reason. The two tests of `setup.js` with a stub installer stay on all
platforms. The Linux service task replaces or extends the installer and its
tests.

### `scripts/dev`

- Add `SHELL="$SHELL"` to `DEV_ENV`. Panel shells then use the user's shell,
  as they do under the login service, where launchd's login shell and systemd
  both set `SHELL`. An unset `SHELL` keeps today's fallback.
- Keep the process name in the port-in-use message when `lsof` exists, and
  print the message without it otherwise:

  ```bash
  holder=$(command -v lsof >/dev/null && lsof -tiTCP:"$PORT" -sTCP:LISTEN | xargs ps -o command= -p)
  echo "Port $PORT is already in use${holder:+: $holder}" >&2
  ```

  Linux has no port-to-process tool installed everywhere (`ss` is Linux-only
  and shows the process only for the user's own sockets), and the message's
  main job, saying the port is taken, needs none.

The rest of `scripts/dev` without `--app` uses only portable commands. The
`--app` path (`lsregister`, the `.app` bundle) belongs to the Linux bundle
task.

## Test plan

- `plugins/internal/plugin/process_test.go`: add a test that starts `sh -c
  'echo why >&2; exit 3'`, reads until the output ends, then writes to
  `Stdin` and gets the exit reason (`exit status 3` and `why`). Writing after
  `Read` returns is deterministic: `Wait` has closed the pipe.
- The existing `TestStartReportsAProcessThatEnds` (Codex, Pi) and
  `TestStartFailedResume` (Claude Code) cover the race through each plugin's
  start. Run them with `-race -count=100` in a Linux container.
- `internal/workspace` worktree tests pass on macOS and in a Linux container.
- `TestTranscriptKeepsOrderAndReplacesItems` and
  `TestTerminalResizeHangupAndRetention`: `-race -count=20` in a Linux
  container and on macOS.
- `make check` passes on macOS and in an ARM64 Linux container. Copy the
  source to a temporary directory rather than mounting the checkout
  read-write, run as a non-root user with `docker run --init`, set `GOPATH`
  to the user's home so `go install` for Hugo can write the checksum
  database, and install Bun at the version in `internal/ui/package.json`
  (`unzip` is needed for the Bun installer).
- The CI jobs run on all three runners after the change is pushed; the parent
  decides when to push.
- `scripts/dev`: run `make dev` on macOS and check that a panel shell starts
  and the port message still names the process. On Linux, check
  `scripts/dev`'s port message path in a container without `lsof`.

## Implementation plan

1. `plugins/internal/plugin/process.go`: wrap the stdin pipe in a writer that
   returns the exit reason after a failed write; update `Process`'s and
   `Stdin`'s comments. Add the process test.
2. `plugins/claude/main.go`: in `initialize`, leave a failed first write to
   `read`'s report on `ready`.
3. `plugins/codex/discovery.go`: wrap only `*plugin.RPCError` from
   `initialize` as an incompatible app-server.
4. `internal/workspace/workspace.go`: choose the clone flag by platform; update
   `copyIncluded`'s comment.
5. `internal/session/transcript_test.go`: wait on the finished text item.
6. `internal/hold/hold_test.go`: `exit 0` in the HUP trap.
7. `desktop/setup.test.js`: run the two installer tests on macOS only.
8. `scripts/dev`: pass `SHELL`; make the port message work without `lsof`.
9. `.github/workflows/check.yml`: the three-runner matrix.
10. `docs/configuration.md`: the clone text.
11. Run the tests and `make check` as in the test plan.
