# Activity dot in pane titles

## Goal

Each pane's label row shows whether its agent has a turn in progress: a dot
right after the agent's name, green (`colors::RUNNING`) while the agent's
`activity` is `store::BUSY` and gray (`colors::QUIET`) while it is
`store::IDLE`. Orchestrators and workers both show it. The dot follows the
state file within a second while a client is attached.

## Related code

- `src/host.rs` `TeamChrome` — shares per-pane flags with the host through
  `Rc<RefCell<…>>`; `attention: Rc<RefCell<Vec<PaneId>>>` is the pattern to
  follow.
- `src/host.rs` `draw_label` — builds the label's left text and its colored
  `spans`; the attention bell is appended after the name only if
  `name_width + 2` fits in `p.rect.cols - 2`.
- `src/host.rs` `Host::read_bar` — on each attach and every `BAR_REFRESH_MS`
  (1000 ms) while a client is attached, loads the state file, recomputes the
  panes' attention flags, the teams, the task counts, and the orchestrators'
  branch, and calls `mux.invalidate_chrome()` when any changed.
- `src/host.rs` `Host` fields `attention`, `bar_read`, and the `TeamChrome`
  construction in `Host::new` (around line 930) and the test helper
  `chrome()` (around line 2300).
- `src/store.rs` — `BUSY`, `IDLE`, `EXITED`, `Agent::activity`.
- `src/hook.rs`, `src/wait.rs`, `src/mcp.rs` — set `activity`; unchanged.
- `src/icons.rs`, `src/colors.rs` — icon and color constants with their
  meanings in doc comments.
- `scratch/mockup.py` `draw_label` and `ICONS` — mirrors `draw_label`.
- `tests/integration.rs`
  `title_attention_refreshes_even_when_the_workspace_dot_does_not_change` —
  the model for the integration test.

## Decisions

- **Refresh through `read_bar`.** The host already loads the state file every
  second while a client is attached, for the attention bells. The activity
  flags are computed from that same load, so the change adds no file reads,
  no processes, and no wakeups; a dot changes at most `BAR_REFRESH_MS` after
  a hook writes the state. The hooks do not notify the host. While no client
  is attached nothing is drawn, and the attach's own `read_bar` brings the
  dots current.
- **Which panes.** Every pane whose agent's `activity` is `BUSY` or `IDLE`,
  orchestrators and workers alike. A pane with an exit status
  (`PaneView::status`, which covers given-up agents and failed launches) shows
  no dot, and neither does an agent whose `activity` is anything else
  (`EXITED`, or empty before its first hook). The flags are keyed by pane, as
  `attention` is, so hidden teams' panes cost nothing to draw.
- **Placement.** The dot goes directly after the label text (the name), before
  the attention bell, so a busy agent waiting for an approval reads
  `name ● 🔔`. The dot is drawn only if `" " + dot` fits whole in the row's
  text width, as the bell is; the bell's fit check then counts the dot.
- **Glyph.** `icons::ACTIVITY`, nf-fa-circle `'\u{f111}'`, one glyph for both
  states, told apart by color, like the other Nerd Font icons the chrome
  draws.
- **Colors.** `RUNNING` and `QUIET` keep their meanings (busy or running,
  idle or stopped) and now also cover an agent's dot. In bold on the focused
  pane, as the bell is.
- **Shared value.** `TeamChrome::activity: Rc<RefCell<Vec<(PaneId, bool)>>>`,
  the panes with a busy (`true`) or idle (`false`) agent. `draw_label` takes
  `busy: Option<bool>` next to `attention: bool`.

## Test plan

Unit tests in `src/host.rs`, beside the attention-dot tests:

- `title_activity_dots_follow_names_before_bells`: three panes with
  `activity` set to busy, idle, and absent, the first also with attention and
  a note. Rows read `━ orch \u{f111} \u{f0f3} · ↑2 `, `w1 \u{f111} ` and
  `w2 ` with no dot. The busy dot is `RUNNING`, the idle dot `QUIET`, the
  bell still `ATTENTION`, and the focused pane's dot is bold.
- `title_activity_dots_skip_exited_panes`: a pane with `status: Some(127)`
  and an activity flag shows no dot.
- `title_activity_dots_are_only_drawn_if_the_whole_dot_fits`: as the
  attention test, at the width where the dot just fits and one column less;
  with attention too, the bell drops before the dot.
- Update `title_attention_dots_follow_names_before_notes_and_keep_focus_style`
  and `title_attention_dots_are_only_drawn_if_the_whole_dot_fits` only as far
  as the new `chrome()` field requires; they set no activity and keep their
  expected rows.

Integration test in `tests/integration.rs`:

- `title_activity_follows_the_state`: start, create `w1` with the `fast`
  profile, `wait_idle` both; wait for `orchestrator \u{f111}` and
  `w1 \u{f111}`. Set the orchestrator's `activity` to `""` in the state and
  wait for `orchestrator \u{f111}` to disappear while `w1 \u{f111}` stays; set
  it back to `IDLE` and wait for it to return. This covers the host picking
  up a change written by another process; colors are covered by the unit
  tests.

## Implementation plan

1. `src/icons.rs`: add `ACTIVITY: char = '\u{f111}'`, "After an agent's name:
   whether it has a turn in progress (nf-fa-circle)."
2. `src/colors.rs`: extend the doc comments of `RUNNING` (a busy agent's dot
   in its title) and `QUIET` (an idle agent's dot in its title).
3. `src/host.rs` `TeamChrome`: add `activity: Rc<RefCell<Vec<(PaneId,
   bool)>>>` with a doc comment ("Panes whose agents are busy (true) or idle
   (false), refreshed with the bar."). In `Chrome::draw`, look up each shown
   pane's entry and pass it to `draw_label`.
4. `src/host.rs` `draw_label`: take `busy: Option<bool>`. When `p.status` is
   `None` and `busy` is `Some`, and `name_width + 2` fits, append
   `" " + icons::ACTIVITY` and push a span in `RUNNING` or `QUIET`. Compute
   the bell's fit from the text width after the dot. Update the doc comment.
5. `src/host.rs` `Host`: add the `activity` field beside `attention`, create
   the `Rc` in `Host::new`, and share it with the chrome. In `read_bar`,
   build the `(PaneId, bool)` list from the loaded state alongside the
   attention list (`BUSY` → `true`, `IDLE` → `false`, other values skipped),
   compare, store, and set `changed`. Update `read_bar`'s and `bar_read`'s doc
   comments to name the activity flags.
6. `src/host.rs` tests: add `activity: Rc::default()` to `chrome()` and the
   unit tests above.
7. `tests/integration.rs`: add `title_activity_follows_the_state`.
8. `scratch/mockup.py`: add `"activity"` to both icon sets (`●` plain, ``
   nerd), `RUNNING` and `QUIET` beside `ATTENTION` with the values in
   `colors.rs`, a per-pane `busy` value in the sample panes (busy, idle, missing),
   and in `draw_label` the dot before the bell with the same fit rule, in
   `RUNNING` or `QUIET`.
