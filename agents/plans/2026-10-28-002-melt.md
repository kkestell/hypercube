# Melting closed panes

When `remove_agent` closes a visible worker pane, its content melts off the
bottom edge of the pane, like DOOM's screen wipe, before the pane goes and the
other panes reflow.

## The look

- The pane keeps its place, size, and title row for the whole melt. Nothing
  reflows until the melt ends.
- Every column of the pane's last drawn screen slides down on its own, starting
  after its own short delay and falling faster and faster. Rows that slide past
  the pane's bottom edge are gone. Cells above a column's content are blank
  (default style). At the end the pane is empty.
- Neighbouring columns have similar delays, so the top edge of the falling
  content is a ragged, wavy curtain, not noise: column 0 gets a random delay of
  0 to 15 steps, and each next column moves its neighbour's delay by -1, 0, or
  +1 step, clamped to 0..=15. One step is `MELT_DELAY_MS / 15`.
- A column's drop, in rows, at `elapsed` ms after the melt began:
  `s = elapsed - delay`; 0 while `s <= 0`, otherwise
  `rows * s * s / (MELT_FALL_MS * MELT_FALL_MS)`, at most `rows`, where `rows`
  is the pane's height. Integer math in `i64`.
- `MELT_DELAY_MS = 300`, `MELT_FALL_MS = 600`, so a melt takes 900 ms.
- The program is hung up when the melt starts, exactly as `remove_pane` does
  now; the focus and host input leave the pane at once.

## Mux (`src/mux.rs`)

- `struct Melt { start: i64, delays: Vec<i64>, rows: Vec<RowBuf> }` and
  `Pane::melt: Option<Melt>`, with `pub fn melting(&self) -> bool`.
- Delays come from a small xorshift64 seeded with `now_ms()` and the pane id.
  No new dependency.
- `pub fn melt_pane(&mut self, id: PaneId)`: if the pane has an empty rect
  (hidden by a zoom, the overlay, or the list of keys), or already melts, act
  like `remove_pane` (or do nothing if already melting) and return. Otherwise:
  capture the frame if the pane isn't held (so the snapshot is what's on
  screen; a held pane's capture is its last completed frame), take
  `frame.rows_seen` into `Melt::rows`, hang up the program into `orphans`,
  `drop_input_for(id)`, and move the focus off it like `remove_pane` does.
- `Pane::live()` is false for a melting pane, so focus, `restart`, and
  `mark_exited` skip it. Check every caller of `live()` still reads right.
- The pane-under-the-pointer lookup in `mouse` (the `rect.contains` call)
  skips melting panes, so presses and wheel there act as on the chrome.
- `render` draws a melting pane with a new `Pane::draw_melt(out, now)` instead
  of `Pane::render`. It redraws the pane's whole rect every frame: for row `y`
  and column `x`, the source row is `y - drop(x)`; outside the snapshot (or
  past the row's cells) it writes a blank in the default style. Clip to the
  pane's current rect, so a resize mid-melt is harmless; columns past the
  delays get delay 0.
- Wide characters: a `Wide` cell is drawn only if the column to its right has
  the same drop and fits; otherwise a blank. A `SpacerTail` is skipped if the
  column to its left has the same drop (the head covered it); otherwise a
  blank. Factor the per-cell code of `RowBuf::write` (style, SGR, text, the
  column re-sync after a wide char) into a helper both use, rather than
  duplicating it. Ignore the selection in the melt.
- `needs_render` is true while any pane melts, so the runtime draws a frame
  every `FRAME_MS`.
- `pub fn melt_deadline(&self) -> Option<i64>`: the earliest melt's end.
- `pub fn end_melts(&mut self, now: i64)`: removes every pane whose melt has
  ended from `panes`, repaints, and pushes `Notice::Melted(id)` for each.

## Runtime (`src/runtime.rs`)

- At the top of the `wait` loop, before taking notices, call
  `mux.end_melts(now_ms())`.
- `Notice::Melted(id)` maps to a new `Event::Melted(PaneId)`.
- Wake for `mux.melt_deadline()`, like `hold_deadline`, so a melt ends on time
  with no client attached.

## Host (`src/host.rs`)

- `close(id)` keeps the agent's slot, and calls `mux.melt_pane(pane)`. If the
  pane is gone afterwards (it was hidden), finish at once; otherwise
  `Event::Melted(pane)` finishes. Finishing: remove the slot, set `zoomed` to
  `None`, `lay_out()`. A second `close` of a melting agent does nothing.
- The slot stays in `self.panes` during the melt, so any `lay_out` meanwhile
  (resize, zoom, a launch) keeps the melting pane in its place.
- `relaunch` returns early for a melting pane.
- `end` needs no change: it removes every pane, melting or not.

## Docs

- `docs/architecture.md`: the `close {agent}` request and wherever pane removal
  is described say the pane melts away first, about a second, unless hidden.
- `AGENTS.md`: add "the melt of closed panes" to the `src/mux.rs` line.

## Tests

- Unit tests in `src/mux.rs` (see the existing mux tests for setup):
  the drop function at the edges (before its delay, mid-fall, past the end);
  delays stay in range and neighbours differ by at most one step;
  `melt_pane` moves the focus off the pane and makes it not live;
  `end_melts` before the end does nothing, after it removes the pane and
  yields one `Notice::Melted`; a hidden pane given to `melt_pane` is removed at
  once with no notice.
- Existing tests keep passing. `remove_agent` integration tests wait up to 30 s
  for the pane to go, which covers the 900 ms melt.

## Out of scope

No animation for workers whose program exits, for the orchestrator, for
`stop`, or for session end. No configuration switch.
