# Roadmap UI improvements

## Goal

Complete the transcript, empty workspace, and file viewer roadmap items, and
establish why usage windows and Codex MCP approvals do not offer the reported
choices. Installation, upgrade, and recovery validation remain deferred.

## Decisions

The baseline extends the existing transcript components, file reads, and native
browser viewers. No new saved state, media conversion, or preview dependencies
are needed. Changes to the UI and server take effect on reload; no harness
changes are currently necessary.

- Saved Codex transcripts contain an assistant text item consisting of a
  question and its choices immediately before the structured question. Hide
  that exact duplicate in the transcript projection, including while the
  structured question is pending. Preserve other assistant text. Answered
  questions use a compact labeled card with the answer and no unused choices.
- Keep tool arguments and output in one card with separate labeled sections.
  Use the chat pane as a CSS query container so transcript and composer gutters
  shrink together, and leave enough room for copy controls. Increase activity
  indentation using existing layout utilities.
- Preserve the empty title bar's window and layout controls, omit its empty tab
  list, and provide an Add Workspace action when no workspace exists.
- Use Shiki's bundled GitHub Light Default and Dark Default themes, matching
  the current themes in primer/github-vscode-theme. Delete vendored After Dark.
- Extend file reads with preview metadata for images, audio, video, PDF, and
  HTML, using native browser elements. Serve preview bytes with range support
  through the existing session file access rules. A path-based preview URL
  allows HTML's relative resources to resolve. Preserve the existing sandbox
  policy for active content. Keep source viewing for textual previews and the
  text viewer's size limit; do not apply that limit to browser previews.
- Codex's current stored reading and captured rate-limit event contain only a
  seven-day primary window. Keep displaying actual reported windows; do not
  invent a five-hour reading. Verify both-window presentation with a fixture.
- The installed Codex 0.166.0 elicitation schema still omits a tool identifier.
  Keep Always allow blocked on that upstream information.

## Implementation plan

1. Update transcript projection and presentation, responsive chat layout, and
   empty workspace presentation in their existing modules.
2. Replace syntax themes and remove obsolete theme assets and license copying.
3. Extend file serving and file state with preview metadata; add native browser
   rendering and retain source mode where the file is text.
4. Cover duplicate questions, tool sections, empty workspace action, both usage
   windows, preview serving and range requests, and preview state refresh.
5. Update the roadmap with completed items and remaining external constraints.
   Update the existing file viewer guide for the new behavior.

## Test plan

Use existing transcript and file component tests, API tests, and Go HTTP tests
for changed behavior. Verify that regular text, binary rejection, conditional
reads, deleted files, relative file access restrictions, source switching, and
preview refresh still work. Run the repository checks and obtain one independent
code review. Open the development server for the user's visual checks; the
padding/hover report remains visually unverified until the user checks it.
