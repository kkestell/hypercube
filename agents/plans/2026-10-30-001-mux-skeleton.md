# Mux skeleton and minimal working path

## Goal

Task 1 of milestone 1 in `agents/mux-design.md`. Create the `mux/` Go module
with a Makefile that builds libghostty-vt and runs the tests, and hook it into
the top-level `make check`. When the task is done:

- A server listens on `$XDG_STATE_HOME/mux/socket`, and the `mux` command
  starts it on first use.
- `spawn` creates a session, window, and pane. The pane's PTY feeds an 80 by
  24 libghostty terminal with 10,000 lines of scrollback.
- `capture` returns the pane's screen as plain text.
- `mux spawn [command...]` prints the new IDs.
- `mux attach <session>` shows the one pane full-screen, sized to the
  terminal, and detaches on Ctrl-b d.

- `Makefile` — top-level `check`. Its `go vet ./...` and `go test ./...` skip

- `go.mitchellh.com/libghostty` at `v0.0.0-20261021212106-df1957cbff56`:
  - `NewTerminal`, `WithSize`, `WithMaxScrollbackLines`, `WithWritePty`,
    `Terminal.VTWrite`, and `Terminal.Resize`.

  - `RenderState.Update`, `RowIterator`, `RenderStateRowCells`,
    `Style`, and `Cursor`, for drawing frames.
    `examples/render/main.go` shows the iteration.

  - The bindings' `CMakeLists.txt` pins Ghostty commit

  `zig build -Demit-lib-vt` installs `share/pkgconfig/libghostty-vt-static.pc`.

## Decisions

- **Module and layout.** The module is `github.com/kkestell/hypercube/mux`,
  with Go 1.27.1. It has three packages:
  - `client` holds the wire types and dialing. Hypercube will use it later.
  - `internal/server` holds the server.
  - `cmd/mux` holds the command line and the attach terminal client.
- **Dependencies.** The module depends on `go.mitchellh.com/libghostty` (the
  version above), `github.com/creack/pty` v1.1.24 for PTYs and window sizes,
  and `golang.org/x/term` for raw mode. Tests also use `golang.org/x/sys/unix`.
- **Building libghostty-vt.** The mux Makefile pins the same Ghostty commit as
  the bindings, so the C API matches.
  - It fetches only that commit with `git init`,
    `git fetch --depth 1 origin <commit>`, and `git checkout FETCH_HEAD` into
    `mux/build/ghostty`.
  - It runs `zig build -Demit-lib-vt -Demit-xcframework=false
    -Doptimize=ReleaseFast --prefix $(CURDIR)/build/ghostty-vt`.
  - A stamp file, `build/ghostty-vt/.built`, keeps the build to one run.
  - It exports `PKG_CONFIG_PATH=$(CURDIR)/build/ghostty-vt/share/pkgconfig`
    for every Go command. Linking is static, so the binary needs no library
    path at run time.
  - Planning could not run this build here. The implementer runs it first and
    fixes the flags if they fail.
- **IDs.** The server assigns string IDs with a kind prefix and one counter per
  kind: `s1`, `w1`, `p1`. IDs are never reused while the server runs. The
  prefix lets `mux kill <id>` in task 3 tell the kinds apart.
- **Wire format.** The connection carries JSON lines.
  - `client.Request` is one flat struct: `type`, `session`, `window`, `pane`,
    `dir`, `argv`, `env`, `cols`, `rows`, and `data` (bytes). Each field is
    omitted when empty.
  - `client.Reply` is `ok`, `error`, `session`, `window`, `pane`, and `text`.
  - Later tasks add fields to these same structs.
  - An unknown `type`, an unknown ID, or an empty `argv` gets
    `{"error":"..."}`.
- **Spawning into an existing session.** That is task 2. Until then, `spawn`
  with a non-empty `session` or `window` returns the ordinary "unknown
  session" or "unknown window" error.
- **Attach protocol.**
  - The client sends `attach {session, cols, rows}`. After the `ok` reply, the
    connection carries a stream.
  - The client sends `input {data}` and `resize {cols, rows}` requests.
  - The server sends `client.Output` lines: `{frame}` with bytes for the
    terminal, or `{detached:true}`. The server closes the connection after
    `detached`.
  - The server handles the prefix key, so `bind` can be added later without
    changing the client.
  - In task 1, Ctrl-b `d` detaches, any other key after Ctrl-b is dropped, and
    all other input bytes go to the pane's PTY unchanged.
  - Prefix bytes are matched one at a time across reads.
- **Sizing (decided with the lead).** On attach and on every `resize`, the
  server resizes the session's single pane to the client's size with
  `Terminal.Resize` and `pty.Setsize`. Restoring 80 by 24 on detach waits for
  task 5.
- **Drawing.**
  - Each attach has a `wake` channel with a buffer of one. A pane's reader
    signals it without blocking after each `VTWrite`, and attach and `resize`
    signal it too. A goroutine owned by the attach drains it.
  - On each wake, that goroutine locks the server, calls `RenderState.Update`,
    builds a full frame, unlocks, and writes the frame. Output that arrives
    while a frame is being written folds into the next frame.
  - A frame does the following, in order:
    1. Begins synchronized output (`CSI ? 2026 h`).
    2. For each row, moves to its first column, then writes each cell with SGR
       built from the cell's `Style`: palette colors as palette SGR, so the
       outer terminal's theme shows; RGB colors as true color; and SGR 39 and
       49 when no color is set. A palette changed with OSC 4 is not shown.
       It also sets bold, faint, italic, underline, strikethrough, and inverse.
       An empty cell is a space, and the trailing half of a wide character
       writes nothing.
    3. Places the cursor and sets its visibility.
    4. Ends synchronized output.
  - Diffing against the previous frame waits until full frames prove slow.
- **Concurrency.**
  - One `sync.Mutex` in `Server` guards the session tree and every terminal.
  - Each pane has one reader goroutine. It reads the PTY master, locks, calls
    `VTWrite`, unlocks, and wakes the attached client.
  - The `WithWritePty` callback writes query replies to the PTY master while
    the lock is held. A full PTY input buffer could block it; that is unlikely
    and gets a comment only.
  - When a read fails because the process exited, the reader calls `cmd.Wait`
    to reap it and stops. The pane stays in the tree; task 2 records the
    status.
- **Environment and command lookup.**
  - `cmd.Env` is set to a non-nil copy of `env`, so nothing is inherited. In
    Go, a nil `Env` would inherit the server's environment.
  - `argv[0]` without a slash is looked up in the `PATH` from `env`, not the
    server's. `exec.Command` would use the server's `PATH`, so a small
    `lookPath(name, env)` does it.
  - The working directory is `dir`.
  - `pty.StartWithSize` starts the process with 80 by 24, a new session, and
    a controlling terminal.
- **Socket and server start.**
  - `client.SocketPath()` returns `$XDG_STATE_HOME/mux/socket`, or
    `~/.local/state/mux/socket` when the variable is unset.
  - `mux server` is a hidden subcommand. It creates the directory with mode
    0700. If a dial to the socket succeeds, it exits with an error. Otherwise
    it removes any stale socket file and listens.
  - The other subcommands dial first. If the dial fails, they start
    `os.Executable() server` in a new session with standard input, output,
    and error set to `/dev/null`, release the process, and retry the dial for
    up to two seconds.
  - Two commands starting a server at the same moment is unlikely and gets a
    comment only.
- **`mux spawn [command...]`.**
  - `argv` is the command, or `$SHELL` when none is given.
  - `dir` is the current directory, and `env` is `os.Environ()` unchanged.
  - It prints `s1 w1 p1`: the IDs separated by spaces, on one line.
  - `-s`, `-w`, and `-c` come with later tasks.
- **`mux attach <session>`.**
  - It puts standard input in raw mode and enters the alternate screen, then
    sends `attach` with the terminal size.
  - It forwards standard input as `input`, sends SIGWINCH changes as `resize`,
    and writes each frame to standard output.
  - On `detached` or end of stream, it leaves the alternate screen, shows the
    cursor, resets SGR, and restores the terminal mode.
  - The one-client-per-session rule is task 7. Until then, a second attach
    gets its own stream.
- **Make targets.**
  - `mux/Makefile` has `build` (`bin/mux`), `test`, and `check`. `check` runs
    `go vet ./...`, a `gofmt -l .` check, and `go test -race ./...`.
  - The top-level `check` runs `$(MAKE) -C mux check` after its own steps.
  - `mux/.gitignore` ignores `/build/` and `/bin/`.

## Test plan

Tests live in `mux/cmd/mux/main_test.go`.

- **Test setup.**
  - `TestMain` builds the `mux` binary into a temporary directory. The tests
    run through the mux Makefile, which sets `PKG_CONFIG_PATH`.
  - Each test gets a state directory from `os.MkdirTemp("", "mux")`, not
    `t.TempDir()`. On macOS a socket path must stay under 104 bytes.
  - Each test sets `XDG_STATE_HOME` to that directory.
  - Cleanup reads the server's process ID from the socket peer
    (`unix.GetsockoptInt(fd, unix.SOL_LOCAL, unix.LOCAL_PEERPID)`) and sends
    it SIGTERM. The server has no exit path until task 3. Pane processes die
    when the PTY masters close.
  - Screen assertions poll `capture` until the expected text appears or a
    deadline passes.
- `TestSpawnCommandStartsServer` runs `mux spawn sh -c 'echo ready; sleep 60'`
  with no server running.
  - The output matches `^s\d+ w\d+ p\d+\n$`.
  - The socket exists.
  - `capture` of the printed pane shows `ready`.
- `TestSpawnDirAndEnv` sets `MUX_TEST_LEAK=1` in the test's own environment,
  then starts the server. It spawns `sh -c 'pwd; stty size; env'` with these
  settings:
  - `dir` is a temporary directory resolved with `filepath.EvalSymlinks`,
    because `/var` is a symlink on macOS.
  - `env` is `PATH=/usr/bin:/bin` and `MUX_TEST=hello`.

  `capture` shows these results:
  - The resolved directory.
  - `24 80`.
  - `MUX_TEST=hello`.
  - No `MUX_TEST_LEAK`.
- `TestAttachSizeAndDetach` spawns `sh`, attaches at 100 by 30, receives a
  frame, and sends `stty size\r` as input.
  - `capture` shows `30 100`.
  - After the input `\x02d`, the stream returns `detached` and then ends.
- `TestErrors` checks that each of these returns an error:
  - `capture` of an unknown pane.
  - `spawn` with an empty `argv`.
  - An unknown request type.
- By hand: `mux spawn`, then `mux attach s1`, shows a working shell at the
  terminal's size. Ctrl-b d returns to the outer shell.

## Implementation plan

1. Create `mux/go.mod`, `mux/.gitignore`, and `mux/Makefile` with the
   Ghostty fetch and build, `build`, `test`, and `check`. Run the libghostty
   build once and confirm that `go build` links the bindings.
2. Add `$(MAKE) -C mux check` to the top-level `Makefile` `check` target.
3. Write `mux/client/client.go`: `SocketPath`, `Request`, `Reply`, `Output`,
   `Dial(path) (*Conn, error)`, `Conn.Call(Request) (Reply, error)` (errors
   from `Reply.Error` become Go errors), `Conn.Send`, `Conn.ReadOutput`, and
   `Close`.
4. Write `mux/internal/server/pane.go`. A `pane` holds the ID, the command,
   the PTY master, the `*libghostty.Terminal`, and the `RenderState`. Add
   `startPane(dir, argv, env)` (`lookPath`, `pty.StartWithSize`,
   `NewTerminal` with `WithSize(80, 24)`, `WithMaxScrollbackLines(10000)`,
   and `WithWritePty`), the reader goroutine, `resize`, and `capture`.
5. Write `mux/internal/server/server.go`. `Server` holds the mutex, the
   counters, the sessions (each with its windows, each with its panes), and
   the attached clients. Add `Listen(path)`, a goroutine for each connection
   that decodes requests, and the `spawn` and `capture` handlers.
6. Write `mux/internal/server/attach.go`: the attach handler, the stream
   loop for `input` and `resize`, the prefix state, the `wake` and draw
   goroutine, and `drawFrame`.
7. Write `mux/cmd/mux/main.go` with the `server` and `spawn` subcommands and
   start-on-first-use, and `mux/cmd/mux/attach.go` with the terminal client.
8. Write `mux/cmd/mux/main_test.go` with the tests above, run `make check`,
   and do the hand check with a `make -C mux build` binary and a temporary
   `XDG_STATE_HOME`.
