# Mux `respawn`

## Goal

Task 4 of milestone 1 in `agents/mux-design.md`. When the task is done,
`respawn {pane, dir, argv, env}` starts a new process in an existing pane
with a fresh screen. If the pane's process is alive, it is hung up. The pane
keeps its ID and its place in its window, and `list` shows it alive.

## Related code

- `mux/internal/server/server.go` — `handle`, `spawn` (checks `argv`, calls
  `startPane`), `kill` and `removePane`, and `findPane`.
- `mux/internal/server/pane.go` — `pane`, `startPane`, `readPane` (records
  the exit and frees a killed pane), `hangUp` (sets `killed`, frees a dead
  pane at once, otherwise sends SIGHUP to the process group), `free`, and
  `resize`.
- `mux/internal/server/attach.go` — `attachment` holds the `*pane` it shows.
  `draw` and `stream`'s resize read `a.pane` under the mutex; `stream`'s
  input reads `a.pane.ptmx` without it.
- `mux/client/client.go` — `Request` already has `Pane`, `Dir`, `Argv`, and
  `Env`.
- `mux/cmd/mux/main_test.go` — `startServer`, `spawnPane`, `waitCapture`,
  `waitExited`, `panePID`, `waitGone`, `killable`, `checkList`, `alive`,
  `dial`, and `TestErrors`.

## Decisions

- **A respawn replaces the `*pane` with a new one that has the same ID.**
  `Server.respawn` starts a new pane with `startPane(req.Pane, ...)`, puts it
  at the old pane's index in its window's `panes`, moves attachments to it,
  and calls `hangUp` on the old pane. The old pane then leaves the tree
  exactly as a killed one does: `hangUp` frees it at once if it is dead, or
  its `readPane` frees it after the process ends. Its late exit writes only
  to the old `*pane`, so it never touches the new process's state. When
  `exited` events arrive in a later task, the old pane's `killed` flag
  already marks an exit that must not be reported.
- **Start first, then hang up.** If `startPane` fails, for example because
  the command is not in `PATH`, `respawn` returns the error and the pane
  keeps its old process and screen.
- **The new pane keeps the old pane's size.** `pane` gains `cols, rows
  uint16`, set by `startPane` and by `resize`. `startPane` takes `cols,
  rows`; `spawn` passes `defaultCols, defaultRows`, and `respawn` passes the
  old pane's size, so a pane respawned while attached matches the client's
  terminal.
- **Attachments follow the pane.** `respawn` sets `a.pane` to the new pane
  for every attachment showing the old one, and signals it, so the client
  sees the fresh screen without reattaching. Because `a.pane` can now change,
  `stream`'s input reads `a.pane.ptmx` under the mutex and writes outside
  it. Input that races a respawn may go to the old PTY and be lost; that
  needs no code.
- **Request.** `respawn` needs `pane` and a non-empty `argv`. Errors: `respawn
  needs a command` and `unknown pane "p9"`, the same text as `spawn` and
  `capture`. The reply is a bare `ok`. `dir` and `env` behave as in `spawn`:
  the process gets exactly `env`.
- **No command-line command.** The design's command line has no `respawn`,
  so this task adds none.

## Test plan

Tests go in `mux/cmd/mux/main_test.go`. A helper `respawnPane(t, c, pane,
argv)` sends `respawn` with `PATH=/usr/bin:/bin` and fails the test on error.

- `TestRespawnDeadPane`: one window holds a pane running `sh -c 'echo old;
  exit 3'` and a second live pane. After `waitExited`, respawn the first with
  `sh -c 'echo new; exec sleep 60'`.
  - `waitCapture` shows `new`, and the screen does not contain `old`.
  - `checkList` shows the same session, window, and both panes in their
    original order, all alive with status 0.
- `TestRespawnLivePane`: a pane runs `sh -c 'echo pid=$$; echo old; exec
  sleep 60'`. Read its PID with `panePID`, then respawn it with `sh -c 'echo
  new; exec sleep 60'`.
  - `waitGone` sees the old PID end.
  - `waitCapture` shows `new`, and the screen contains neither `old` nor the
    old PID.
  - `checkList` shows the pane alive.
- `TestRespawnAttached`: attach to a session whose pane runs `killable` at
  100 by 30, and read the first frame. Respawn the pane with `sh -c 'stty
  size; exec sleep 60'`.
  - Frames keep arriving until one contains `30 100`, which shows the stream
    follows the new pane and the new pane kept the client's size.
- `TestErrors` gains: `respawn` with no command, `respawn` of an unknown
  pane, and `respawn` with a command not in `PATH`. After the last, `capture`
  of that pane still works and `list` shows it alive.

## Implementation plan

1. In `mux/internal/server/pane.go`, add `cols` and `rows` to `pane`; give
   `startPane` `cols, rows` parameters and use them for the PTY and terminal
   size; record the new size in `resize`.
2. In `mux/internal/server/server.go`, pass the default size from `spawn`,
   add `respawn`, and add its case to `handle`. `respawn` finds the pane and
   its index under the mutex, starts the new pane, swaps it in, moves
   attachments, and hangs up the old pane.
3. In `mux/internal/server/attach.go`, read `a.pane.ptmx` under the mutex in
   `stream`'s input case.
4. In `mux/cmd/mux/main_test.go`, add `respawnPane`, the three tests, and the
   `TestErrors` cases.
