# Mux layout and resizing

## Goal

Task 5 of milestone 1 in `agents/mux-design.md`. An attached client now shows
every pane of its session's first window instead of one pane full-screen. The
first pane is the main pane, on the left at 40% of the width. The other panes
stack on the right in equal heights. The client's terminal size sets every
pane's size in the session. When the client detaches, the panes go back to 80
by 24. Panes that do not fit are not drawn. Input goes to the focused pane,
and the cursor is drawn where that pane's cursor is.

The layout keeps the two bar rows at the top and a title row above each pane
empty, so task 6 can draw them without changing any pane size.

## Related code

- `mux/internal/server/attach.go` — `attachment` holds the one `*pane` it
  shows. `attach` resizes that pane to the client's size, `stream` routes
  input to it and handles `resize`, `draw` and `drawFrame` render its screen
  at row 1, column 1, and `wake` signals the attachments showing a pane.
- `mux/internal/server/pane.go` — `pane.resize` sets the terminal and PTY
  size and records `cols` and `rows`. `startPane` takes the starting size.
- `mux/internal/server/server.go` — `spawn` appends a pane to a window,
  `kill` and `removePane` close attachments that show a removed pane, and
  `respawn` moves attachments to the new pane.
- `mux/cmd/mux/main_test.go` — `startServer`, `spawnPane`, `respawnPane`,
  `waitCapture`, `killTarget`, `dial`, and the attach tests
  `TestAttachSizeAndDetach`, `TestAttachKeepsPaletteColors`,
  `TestKillEndsAttach`, and `TestRespawnAttached`.

## Decisions

- **An attachment shows a session.** `attachment` replaces `pane *pane` with
  `session *session` and records the client's terminal size in `cols, rows
  int`. Two methods derive the rest, so no state goes stale when panes come
  and go:
  - `a.window()` is `a.session.windows[0]`. Task 7 adds window switching.
  - `a.focus()` is the shown window's main pane, `panes[0]`. Task 7 adds `o`
    and a stored focus. Until then, killing the main pane moves focus to the
    next pane, which becomes the main pane.
- **The layout.** A new file `mux/internal/server/layout.go` holds the
  constants and one pure function.
  - `barRows = 2` and `titleRows = 1`. The pane area starts below the bars.
    Each pane's rectangle in the area has a title row above its screen.
  - `rect` is `x, y, cols, rows int`: the pane's screen, 0-based, in terminal
    cells. Its title row is row `y-1`.
  - `layout(n, cols, rows int) []rect` returns rectangles for the first panes
    that fit, in window order, so its length may be less than `n`.
  - With one pane, the main pane takes the full width. With more, the main
    pane is `cols*40/100` columns wide, one column draws a divider, and the
    stacked panes take the rest of the width.
  - The area's height `rows - barRows` is split among the stacked panes. Each
    pane needs its title row and one screen row, so at most `area/2` stacked
    panes are shown, and the rest are skipped. Each shown pane gets
    `area/shown` rows, and the first `area%shown` get one more.
  - The main pane is shown when the area has two rows. A terminal too narrow
    for the stack (fewer than three columns) shows no stacked panes; that is
    unlikely and needs only a comment.
  - At 100 by 30, a window of four panes gives the main pane 40 by 27 and the
    stacked panes 59 by 9, 59 by 8, and 59 by 8.
- **`layoutSession` owns pane sizes.** `Server.layoutSession(sess)`, called
  with the mutex held, finds the attachment showing `sess`. If there is one,
  it sizes the panes of every window in the session to `layout(len(w.panes),
  a.cols, a.rows)`, so switching windows in task 7 needs no resize. If there
  is none, every pane goes back to 80 by 24. Panes that are skipped keep
  their size. It calls `pane.resize` and panics on an error: the layout never
  gives a zero size, and a PTY master accepts a size after its process has
  exited. It is called from:
  - `attach`, after the attachment is added;
  - `stream`'s `resize`, after recording the new size;
  - the end of `attach`, after the attachment is removed, when the session
    still exists;
  - `spawn`, after the pane joins the tree, so a pane spawned into an
    attached session starts at 80 by 24 and is resized at once;
  - `kill`, for every session that still has an attachment.
  `pane.resize` returns early when the size is unchanged.
- **One attachment per session is assumed.** If two clients attach to one
  session, `layoutSession` uses whichever it finds first. A comment names
  this; task 7 detaches the first client.
- **Kill.** `removePane` no longer closes attachments; it only hangs up the
  pane. After the tree is updated, `kill` closes and removes the attachments
  whose session is gone and calls `layoutSession` and signals the
  rest, since their window may have lost panes. `stream`'s `resize` keeps its
  check that the attachment is still registered.
- **Respawn.** `respawn` no longer moves attachments; it calls `s.wake(p)` for
  the new pane, which keeps the old pane's size.
- **Wake.** `wake(p)` signals each attachment whose shown window contains `p`.
  `spawn` and `kill` signal the session's attachment directly.
- **Input.** `stream` writes input to `a.focus().ptmx`, read under the mutex
  as now.
- **Drawing.** `drawFrame(a)` draws the shown window under the mutex:
  - It begins with the synchronized update, an SGR reset, cursor home, and
    `\x1b[2J`. Clearing the screen inside the synchronized update blanks the
    bars, title rows, and skipped space without drawing them.
  - Each shown pane's render state is updated and its rows are drawn as now,
    each row starting at `\x1b[{rect.y+row+1};{rect.x+1}H`.
  - When stacked panes are shown, the divider column draws `│` with the
    default style on every row of the pane area.
  - The cursor goes to the focused pane's cursor plus its rectangle's offset,
    and is hidden if that pane's cursor is hidden or the pane is not shown.

## Test plan

Tests go in `mux/cmd/mux/main_test.go`. New helpers:

- `attachAt(t, session, cols, rows)` dials, attaches, reads the first frame,
  and returns the connection.
- `checkSize(t, c, pane, want)` respawns the pane with `sh -c 'echo size=$(stty
  size); exec sleep 60'` and reads `size=` from its screen, repeating until the
  size is `want` or a deadline passes. Respawn keeps the pane's size, so this
  reads the size of a pane that is not focused. Repeating covers a `resize`
  request, which has no reply.

New tests:

- `TestLayoutSizes`: a session whose first window has four panes, plus a
  second window with one pane. Attach at 100 by 30.
  - The main pane is `27 40`; the stacked panes are `9 59`, `8 59`, and `8
    59`; the second window's pane is `27 100`.
  - Send `resize` to 120 by 40. The main pane is `37 48` and the last stacked
    pane is `11 71`.
  - Detach with Ctrl-b d and read until `detached`. The main pane and the
    last stacked pane are `24 80`.
- `TestLayoutSkipsPanes`: a window of four panes. Attach at 100 by 7. The
  main pane is `4 40`, the first two stacked panes are `2 59` and `1 59`, and
  the third, which does not fit, is `24 80`.
- `TestLayoutFollowsSpawnAndKill`: attach at 100 by 30 to a session with one
  pane, which is `27 100`. Spawn a second pane into the window: the main pane
  is `27 40` and the new pane `27 59`. Kill the new pane: the main pane is
  `27 100`.
- `TestInputGoesToMainPane`: a window of two panes running `cat`. Attach and
  send `routed\r`. The main pane shows `routed`; the other does not. Kill the
  main pane and send `second\r`: the remaining pane shows `second`.
- `TestCursorAndOffsets`: a main pane running `sh -c 'printf abc; exec sleep
  60'` and a stacked pane running `sh -c 'printf STACK; exec sleep 60'`.
  Attach at 100 by 30 and read frames until one contains `abc` and `STACK`.
  That frame contains `\x1b[4;42H`, the start of the stacked pane's first
  row, and ends with `\x1b[4;4H\x1b[?25h\x1b[?2026l`, the main pane's cursor
  after `abc`.

Existing tests change for the reserved rows:

- `TestAttachSizeAndDetach` and `TestRespawnAttached` expect `27 100` instead
  of `30 100`.
- `TestAttachKeepsPaletteColors` attaches at 20 by 5, since 20 by 3 leaves no
  room for the pane.

## Implementation plan

1. Add `mux/internal/server/layout.go` with `barRows`, `titleRows`, `rect`,
   and `layout`.
2. In `mux/internal/server/pane.go`, return early from `resize` when the size
   is unchanged.
3. In `mux/internal/server/attach.go`, change `attachment` to hold `session`,
   `cols`, and `rows`; add `window` and `focus`; add `layoutSession`; update
   `attach`, `stream`, `wake`, `draw`, and `drawFrame` as described.
4. In `mux/internal/server/server.go`, call `layoutSession` and signal from
   `spawn` and `kill`; drop attachment handling from `removePane` and
   `respawn`, and wake the new pane in `respawn`.
5. In `mux/cmd/mux/main_test.go`, add `attachAt`, `checkSize`, and the five
   tests, and update the three existing attach tests.
