# Claude Code

## 1. Overview

- **[verified]** `claude --version`: `2.1.314 (Claude Code)`. Top-level and auth-status help checked; no model calls or sessions started.
- **[docs]** Anthropic's proprietary Claude Code CLI; public issue/changelog/examples repository is not the complete harness source. Native installer, Homebrew/WinGet and platform binaries are supported. Source: https://code.claude.com/docs/en/setup
- Exact current license wording, release cadence guarantee, numerical adoption: unknown. Current docs explicitly include features as recent as 2.1.304; do not rely on older pre-mods/pre-daemon descriptions.

## 2. Interactive terminal interface

- **[docs]** Classic scrolling and fullscreen renderers coexist. `CLAUDE_CODE_NO_FLICKER=1` selects fullscreen; `/tui fullscreen` persists preference and relaunches intact. `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1` forces synchronized output where detection misses support. `--ax-screen-reader` forces flat classic output except attached background sessions. Sources: https://code.claude.com/docs/en/terminal-config and local help.
- **[docs]** Title includes session name/status glyph; `CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1` disables title/status probing. OSC 7501 Program Status Protocol supported >=2.1.295 after terminal support negotiation, reports working/waiting/done; glyph omitted if terminal supports protocol. Background sessions do not report OSC 7501 even while attached. tmux is probed rather than outer terminal; passthrough doesn't fix this. Source: https://code.claude.com/docs/en/terminal-config
- **[docs]** Default notifications: Ghostty/Kitty/iTerm2 desktop notifications; Apple Terminal silent BEL if Audible bell disabled, otherwise nothing; other terminals nothing. `preferredNotifChannel:"terminal_bell"` forces BEL. Notification hooks supplement rather than replace builtins. Progress bar forwarding and notifications need tmux `allow-passthrough on`; focus events and extended keys needed for reliable Shift+Enter. Source: same terminal reference.
- **[docs]** Ctrl+J or backslash+Enter newline universal; Kitty keyboard negotiation supports modern terminal Shift+Enter >=2.1.269; some integrated terminals need `/terminal-setup`, which changes user terminal/editor config (not run here). VS Code large paste can drop characters; use files for large content. Screen-reader/fullscreen mouse/scrollback semantics differ. Source: same reference.
- Exact OSC 9/9;4/title bytes, all mouse/resize sequences: unknown; no live TUI capture. OSC 7501 wire payload was not independently traced.

## 3. Launch and configuration

- **[help]** Per-process main flags: `--settings <file-or-json>`, `--setting-sources user,project,local`, `--system-prompt`, `--append-system-prompt`, `--agents <json-or-file>`, `--agent`, `--tools`, `--allowedTools/--allowed-tools`, `--disallowedTools/--disallowed-tools`, `--add-dir`, model/effort/permission flags, `--mcp-config <files-or-json...>`, `--strict-mcp-config`, repeated `--plugin-dir` or `--plugin-url`, debug filters/file, name/session selectors, chrome/IDE/cloud/background/worktree controls.
- **[docs]** `--system-prompt-file`, `--append-system-prompt-file`, subagent append variants, `--max-turns`, `--permission-prompt-tool`, `--channels`, `--teammate-mode` are documented though not all top-level help lists them. Since 2.1.283 text+file versions can combine; file content comes first. Replacement drops default identity/tool/safety guidance. Source: https://code.claude.com/docs/en/cli-reference
- **[docs]** Precedence highest first: managed policy > flag-settings (`--settings`) > `.claude/settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json`. Lists usually union, not replace; exceptions `fallbackModel`, `modelPicker`, managed `availableModels`, per-model `modelSettings`. Env precedence is variable-specific, not a simple layer. Source: https://code.claude.com/docs/en/settings
- **[docs]** `CLAUDE_CONFIG_DIR` isolates settings/history/plugins and most auth; `~/.claude.json` also contains trust/account/MCP/global state. Local settings in git normally live at repository/main checkout root, but shared settings read from primary working directory; managed settings still apply when source selection excludes user/project/local. Source: same settings reference.
- **[help]** `--bare` sets `CLAUDE_CODE_SIMPLE=1`; skips hooks/LSP/plugin sync/attribution/memory/prefetch/keychain/CLAUDE.md discovery; only API key or explicit apiKeyHelper Anthropic auth, not OAuth. Skills still resolve explicitly. `--safe-mode` disables customizations but keeps normal auth/tools/permissions and managed policy. `--restricted` removes code-running/WebFetch tools unless explicitly named, ignores normal user/project/local settings, confines file tools to working dirs and refuses bypassPermissions. These modes are not interchangeable.
- **[docs]** Settings reload while running (permissions/hooks/helpers included); model/effort changes need dedicated runtime controls. Project allow rules/env wait for trust, deny/ask apply immediately. `-p` skips trust dialog and silently drops invalid non-managed settings rather than showing UI; run `doctor` diagnostics separately. Source: https://code.claude.com/docs/en/settings
- **[docs]** System prompt snapshot defaults on: first request records fully composed prompt; resuming with different prompt flags does not change it until compaction. `--system-prompt-snapshot off` rebuilds per request; bare outside cloud/background defaults off. `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` splits cached/static and dynamic prompt >=2.1.275. Source: https://code.claude.com/docs/en/cli-reference

## 7. Hooks and events

- **[docs]** Exact settings event list: `SessionStart`, `Setup`, `UserPromptSubmit`, `UserPromptExpansion`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `MessageDisplay`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `ElicitationResult`, `SessionEnd`. Source: https://code.claude.com/docs/en/hooks
- **[docs]** Per-process config `--settings '{"hooks":{"EVENT":[{"matcher":"...","hooks":[{"type":"command","command":"..."}]}]}}'`; settings/plugin hooks additive, not replacement. Types `command|http|mcp_tool|prompt|agent`. Command stdin / HTTP POST JSON share common `session_id,transcript_path,cwd,permission_mode,hook_event_name`, agent context for subagents. Tool events `tool_name,tool_input,tool_use_id` plus response/error for post events; prompt events prompt; stop stop_hook_active/last assistant; lifecycle source/reason; compaction trigger; elicitation server/request/schema. Source: same hooks reference.
- **[docs]** Matchers are exact names/lists when only simple chars, JS regex otherwise; unknown matcher on no-matcher event ignored. Tool `if` uses permission-rule syntax and only applies to tool events. MCP tools `mcp__server__tool`; plugin tool server segment `plugin_<plugin-name>_<server-name>`. FileChanged literal watched filenames and StopFailure matchers have narrower syntax. Source: same reference.
- **[docs]** Common output `continue:false`, stopReason, suppressOutput, systemMessage; event-specific `hookSpecificOutput.hookEventName`. PreToolUse permissionDecision `allow|deny|ask`, reason, updatedInput/additionalContext; PermissionRequest decision can approve/deny; prompt hooks add context/block; Stop/SubagentStop block asks another response; worktree-create stdout supplies path; MessageDisplay transforms visible text; model-switch can block. Exit 2 blocks where event supports it and supplies stderr feedback; other failures usually nonblocking unless configured onFailure:block. Source: same reference.
- **[docs]** Matching handlers run parallel; prompt/agent concurrency max 12. Command/http/mcp defaults 600s, prompt 30s, agent 60s; UserPromptSubmit/PreModelSwitch/PostModelSwitch command/http/mcp defaults 30s; MessageDisplay 10s. SessionEnd shared 1.5s budget, configurable per-hook timeout can raise up to 60s. Timeouts start once waiting LLM handler starts. Source: same reference.
- **[docs]** Command `args` selects exec form without shell; absent args uses shell form (`sh -c` POSIX). Path placeholders CLAUDE_PROJECT_DIR/CLAUDE_PLUGIN_ROOT/CLAUDE_PLUGIN_DATA substituted in exec form; user_config substitution forbidden in shell form. onFailure continue|block >=2.1.295. Source: same reference.
- **[docs]** `async:true` hooks don't block; command timeout not enforced for async. `asyncRewake:true` wakes Claude on exit 2 with stderr or stdout system reminder. Skill once:true removes only after successful execution, failures/block/timeouts leave registered; ignored outside skill frontmatter. Skill hooks last rest of session after invocation, agent hooks only subagent lifetime. Stop loops must use stop_hook_active to avoid repeating; no universal safe loop cap established. Source: same reference.
- **[docs]** SessionStart/Setup happen before MCP client available, so mcp_tool hooks skipped at initial startup; later SessionStart clear/compact may run them. API errors trigger StopFailure values including authentication_failed/model_not_found/rate_limit; EndConversation skips PreToolUse/PostToolUse. Source: same reference.
- **[docs]** onFailure:block covers spawn/exit-non0-or2/HTTP-non2xx/timeout/malformed JSON or schema; plain command stdout text itself not failure. No effect Stop/SubagentStop/TaskCompleted/TeammateIdle or async/asyncRewake. Windows without Git Bash can fail closed for tool hooks even without explicit onFailure; set onFailure deliberately for cross-platform behavior. Source: https://code.claude.com/docs/en/hooks
- **[docs]** In-process function hooks (“mods”) form a second, much broader event/control API; see section 8. Generic command-hook output-byte limit: unknown.

## 9. Tools, permissions, and approvals

- **[help]** Modes `acceptEdits|auto|bypassPermissions|manual|dontAsk|plan`; docs also accept `default` alias of manual. `--allowedTools` autoapproves but **does not restrict catalog**; `--tools` restricts builtins, empty string disables; --disallowedTools bare removes tool, scoped pattern denies calls. MCP excluded from --tools, deny `mcp__*` separately.
- **[docs]** Builtins include shell (Bash/PowerShell), file read/edit/write/patch/notebook/search, web fetch/search, skills, agent/message/background tasks, questions/plan/task tools, worktrees and EndConversation; exact defaults model/platform-dependent. Glob/Grep not default on macOS/Linux/WSL in current docs; tools explicitly opt them in. Source: https://code.claude.com/docs/en/cli-reference
- **[help]** Print `--permission-prompts host|none`: host routes SDK/MCP handler; none denies anything that would prompt, does not change other mode/rule decisions. --dangerously-skip-permissions bypasses, --allow-dangerously-skip-permissions merely enables switching option.
- **[docs]** SDK `canUseTool(toolName,input,options)` returns allow updatedInput or deny message, receives cancellation context; AskUserQuestion answers supplied through permission callback's structured updated input. Only called if earlier permission flow needs prompt, not autoallowed tools. `--permission-prompt-tool mcp__server__tool` alternative print-host route. Source: https://code.claude.com/docs/en/agent-sdk/typescript
- **[docs]** Sandboxing can be configured via SDK sandbox/settings; Bash sandbox does not contain arbitrary mods/process calls. Restricted mode narrows files/tools/settings but isn't a replacement for external OS/container isolation. Source: CLI reference and mods overview.

## 11. MCP

- **[help]** Process `--mcp-config` JSON/files, `--strict-mcp-config` excludes other configured sources; SDK mcpServers and setMcpServers support runtime update. Auth/login management via claude mcp.
- **[docs]** Client supports stdio, HTTP and SSE, tools/resources/prompts/instructions, OAuth and elicitation. `readMcpResource`, reconnectMcpServer, toggleMcpServer, setMcpPermissionModeOverride and mcpServerStatus runtime APIs; SDK in-process createSdkMcpServer/tool register custom tools. Source: https://code.claude.com/docs/en/agent-sdk/typescript
- **[docs]** **Actual unsolicited MCP-to-session push exists:** channel server declares `capabilities.experimental['claude/channel']:{}` then emits `notifications/claude/channel {content:string,meta?:Record<string,string>}`. Keys only letters/digits/underscore; invalid dropped. Events queue in order, busy arrivals batch on next turn; no processing ACK (transport-write success only); unregistered/policy-blocked channels silently drop. Source: https://code.claude.com/docs/en/channels-reference
- **[docs]** Channel research preview needs `--channels plugin:NAME@MARKETPLACE` allowlisted, Anthropic auth/org enabling; custom `--dangerously-load-development-channels server:NAME|plugin:...` interactive confirmation, ignored print/SDK. Stdio local subprocess bridge, not arbitrary remote HTTP server notification. Source: same channel reference.
- **[docs]** Permission relay opt-in `claude/channel/permission:{}`; server receives `notifications/claude/channel/permission_request {request_id,tool_name,description,input_preview}`. Reply `notifications/claude/channel/permission {request_id,behavior:"allow"|"deny"}`; first local/remote response wins, tool approvals only, not trust/MCP consent. ID five lowercase letters excluding l; reused/colliding stale IDs rejected. Preview sanitizes, redacts recognizable secret tokens, max3500 code points per argument field head/tail; description isn't actual command. Source: same reference.

## 17. Anything else a program driving this harness should know

- **[docs]** SDK ships version-matched optional native binary (SDK 0.3.patch maps CLI2.1.patch), can override pathToClaudeCodeExecutable. env option **replaces** child environment, so merge process.env deliberately. SDK default system prompt minimal, not full CLI unless preset claude_code selected. Source: https://code.claude.com/docs/en/agent-sdk/typescript
- **[docs]** `resolveSettings()` computes effective settings/provenance without spawning CLI; doesn't execute policyHelper or fetch server-managed settings, so not identical to live session unless caller supplies managed snapshot. Source: same SDK reference.
- **[docs]** CLI help is intentionally nonexhaustive. Treat feature/version/policy availability as runtime discovery, not hardcode from historical docs; validated local help takes precedence where bare-mode description differs from generalized docs. Source: https://code.claude.com/docs/en/cli-reference
