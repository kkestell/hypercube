# Prior-art survey, first pass

The report of a Hypercube worker (Sonnet), 2026-10-30, as sent. Its comparisons refer to the design in `agents/agent-harness-plugins.md` as it stood then.

Prior-art result for the harness plugin design. Tags: [V] read in docs or source (URL key below), [I] inferred, [S] secondary sources only. No files were touched.

None of the orchestrators found loads third-party executable harness adapters. Herdr, Vibe Kanban, Claude Squad, agent-deck, ccmanager and cmux all have the harness list inside their own code. The nearest cross-vendor standard is ACP, which runs the harness without a terminal.

TAKEAWAYS FOR OUR DESIGN
1. Our shape is not found elsewhere: an executable per harness with `launch` returning argv/env is new. The closest neutral piece is Herdr's report CLI and its per-pane env (HERDR_ENV, HERDR_PANE_ID, socket path), where outside Herdr the call does nothing [V]. That is our HYPERCUBE_AGENT_ID rule: unset means do nothing and reply `{}`.
2. Herdr, cmux and agent-deck write hooks into the user's global config [V]. Per-launch flags and env (our rule) is the unusual choice, and it is correct for isolation. A harness with no per-process config (Gemini, Aider, per our summary) gets no workaround from prior art except global install, so leave it unsupported.
3. Screen scraping (Claude Squad, Herdr fallback, ccmanager, agent-deck fallback) is the common fallback and is described as slow or wrong in places [V]. Herdr and agent-deck use hook or extension state in place of the screen whenever it exists [V]. Build no screen-detection fallback.
4. Herdr stamps each state report with an increasing `seq` and ignores stale ones [V]. Our events come from separate hook processes and could arrive out of order, for example a late `tool` after `stop`. If that shows up in practice, add an optional `seq` or timestamp to events. [I]
5. Approvals: ACP has a blocking request, a reply that is a choice, and a required `cancelled` reply when the turn is cancelled [V]. Vibe Kanban routes every harness through one approval service [V]. Our `approve` (blocking, withdrawn by ending the process, with `defer`) matches both. The one gap is ACP's choice-list shape, which would also serve the deferred "Questions" feature. No change needed now.
6. Delivery: every tmux-based tool types into the pane [V]. agent-deck refuses that fallback and reports failure [V]. Herdr refuses to prompt a blocked pane [V]. Our waiter, which starts only when idle, plus no typing fallback, is the stricter choice. Keep it.
7. Forward compatibility: git helpers tell implementers to silently ignore unknown operations and attributes [V]. Add one sentence to the doc: plugins ignore unknown spec fields and unknown events, and core ignores unknown reply fields. This costs nothing, and we need no version handshake given the no-backwards-compatibility rule.
8. Discovery: kubectl's `plugin list` shows found plugins and warns on non-executables and duplicates [V]. Our "beside the binary, then PATH" lookup needs the same two warnings, probably in the config-load error. Small, and worth doing.
9. `check` could also report "not logged in". Vibe Kanban's availability has an explicit LoginDetected state [V]. A harness that isn't authenticated fails on its first turn, which is the failure `check` exists to move earlier. [I, feasibility per harness unverified]
10. ACP is the only standard that covers many harnesses (Claude, Codex, Pi via adapters; Gemini, Goose, Copilot, OpenCode, Cursor natively) [V], but its agents have no terminal. Our "Deferred: ACP" entry is right. If added later, a launch spec is already close: `mcp` has the same name/command/args/env shape as ACP's `session/new` `mcpServers` [V]. Zed and the ACP registry describe an agent as `command, args, env` data [V/S], which is the same as our `launch` reply.
