# Linux checks in CI and a passing test suite

## Plan

`agents/plans/2026-11-06-012-linux-checks.md`

## Summary

All plan tasks are implemented. `make check` passes on macOS and in an ARM64
Linux container, and the CI job is a matrix over `macos-15`, `ubuntu-24.04`,
and `ubuntu-24.04-arm`. The real runners have not run it yet.

## Departures from the plan

- The plan said `make check` passed in the container with its changes. In a
  bare container, `cmd/hypercube`'s integration test failed
  (`timed out waiting for panel shell PID`) in every run: the panel shell
  uses `$SHELL`, which `docker run` leaves unset, and the fallback `/bin/zsh`
  is not installed. The test now sets `SHELL=/bin/sh` itself, so it does not
  depend on the runner's environment. The production fallback is unchanged.
  The plan was not edited.
- The port message in `scripts/dev` ends with `|| true`. Under `set -e` and
  `pipefail`, the plan's snippet exits the script when `lsof` is missing
  instead of printing the message.
- `SHELL="${SHELL:-}"` in `DEV_ENV` instead of `SHELL="$SHELL"`, because
  `set -u` makes the latter fail when `SHELL` is unset. `terminal.go` treats
  an empty value like an unset one.

## Decisions

- `Process.Stdin` stays an `io.WriteCloser`; the new `stdinPipe` type wraps the
  pipe, so no plugin changed its use of `Stdin`.

## Checks run

- macOS `make check` — passed.
- macOS `go test -race -count=20` of the hold and transcript tests and of the
  start tests in `plugins/...` and the new process test — passed.
- ARM64 Linux container (`golang:1.27.3`, non-root user 1000, `--init`, Bun

- Same container, `go test -race -count=100` of `plugins/codex`, `pi`,
  `claude`, `opencode`, `plugins/internal/plugin` — passed.
- Same container, `-race -count=20` of `TestTerminalResizeHangupAndRetention`
  and `TestTranscriptKeepsOrderAndReplacesItems`; `internal/workspace`
  `-count=5` — passed.

## Manual verification

1. `scripts/dev` on macOS with a server on the dev port prints
   `Port 4291 is already in use: <Python command>`; the process name is kept.
2. `scripts/dev up` on macOS starts a backend whose environment has
   `SHELL=/bin/zsh`. The dev directory and processes were removed afterwards.
3. In the container without `lsof`, the port-message lines under
   `set -euo pipefail` print `Port 4281 is already in use` and continue. The
   check ran the lines alone, not the whole script.

## Follow-up work

- The container's Bun installer provides only `bun`; `make check` needs
  `bunx`, which `setup-bun` on the runners provides. The container had a
  `bunx` symlink added.
- A panel shell with `SHELL` unset still falls back to `/bin/zsh`, which a
  Linux machine may lack.
