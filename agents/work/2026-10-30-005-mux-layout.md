# Mux layout and resizing

## Plan

`agents/plans/2026-10-30-005-mux-layout.md`

## Summary

An attached client now shows every pane of its session's first window: the main pane on the left at 40% of the width, the others stacked on the right with a divider column. The client's size sets every pane's size in the session, and detaching returns them to 80 by 24. Panes that do not fit are skipped. Input goes to the main pane and the cursor is drawn at its position. The two bar rows and each pane's title row stay blank for task 6. The plan's goal is met.

## Decisions

- `layoutSession` also signals the attachment it lays out, so `attach`, `resize`, `spawn`, and `kill` do not each signal separately.
- `removePane` had nothing left but `p.hangUp()`, so `kill` calls `hangUp` directly and `removePane` is gone.
- `stream` checks the attachment is still registered before routing input, as it already did for `resize`. After a kill ends the session, `a.focus()` would index an empty window list.
- `layout` returns nothing when the terminal has no column or fewer than two pane rows, so a degenerate client size cannot give a pane a zero size.
- `checkSize` matches the `size=` line exactly: the capture trims the trailing newline, so a substring match on `27 40` also matches `27 400`-style prefixes.
