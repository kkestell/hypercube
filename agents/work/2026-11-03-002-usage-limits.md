# Show Claude Code and Codex usage limits

## Plan

`agents/plans/2026-11-03-006-usage-limits.md`

## Summary

The Claude and Codex plugins report usage windows as `limits` events; the
session runtime saves the newest reading of each harness window in a `limits`
table; the state message carries them; and the sidebar shows one row per
harness below Add Workspace. The plan's goal is met.

## Departures from the plan

- The architecture review's two amendments were applied and written into the
  plan: each `Limit` carries `At`, the plugin's observation time, and
  `PutLimit` updates a window only when the incoming `At` is later; a window
  past its reset keeps its last percent, dimmed, titled `Reset …`, and a
  window with an unknown reset has no title.
- `TestDecodeChecksFinalItems` is renamed `TestDecodeChecksEvents`, since it
  already covered grants and now covers limits.
- Browser test states that render the sidebar (`app.test.jsx`,
  `sidebar.test.jsx`) gained `limits: []`.

## Decisions

- Both plugins stamp `At` with the current time rather than Codex's
  `emittedAtMs`, so the two harnesses' readings share one clock.
- Row order comes from the server (`Limits` orders by harness, then minutes);
  `Object.groupBy` keeps it.
- `usedPercent` is an int32 in Codex 0.166.0's generated schema, so the Codex
  plugin decodes it as an integer.
