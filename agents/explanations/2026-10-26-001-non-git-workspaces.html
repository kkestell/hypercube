Workspaces outside Git

The plan lets hypercube start in a directory that is not a Git checkout, such as ~/work/strib. In that kind of workspace, each worker runs directly in an existing directory that the orchestrator names, and Hypercube creates no branches or worktrees. Workspaces in Git checkouts keep their current behavior.

Workspaces today

A workspace is the set of agents, the state file, and the tmux session that belong to one directory. Today that directory must be a Git checkout. current() finds it with git rev-parse --show-toplevel and returns an error anywhere else.

The orchestrator runs in the checkout itself. create_agent gives each worker a new branch, hypercube/<name>, created from the orchestrator's HEAD. That branch is checked out in a worktree at <checkout>/.hypercube/<name>. The orchestrator merges a worker's branch into its own branch. remove_agent and hypercube down remove the worktree and the branch, and only after checking that the branch is merged into HEAD and the worktree has no uncommitted changes.

Workspaces outside Git

With the change, running hypercube in a directory that is not a Git checkout makes that directory the workspace root. The orchestrator runs there and has no branch. create_agent takes a dir argument, and the new worker runs in that directory as it is. The directory is usually its own Git checkout, but it does not have to be one, and it does not have to be inside the workspace root.

Nothing is merged into the orchestrator's directory. Each worker commits, or does not, in its own directory, following the orchestrator's instructions. Removing a worker closes its pane and removes it from the state file. The directory and its contents are left as they are.

The no_git field

Several code paths need to know which kind of workspace they are in. The plan adds one field to State, written to the state file as no_git. start() sets it once, when it creates the orchestrator for a new workspace.

cmd/hypercube/main.go, current()

	root, err = workspace.Root(cwd)
	if err != nil {
		return "", "", err
	}
	return root, workspace.Name(root), nil

cmd/hypercube/main.go, current(), planned

	root = cwd
	if workspace.IsRepo(cwd) {
		if root, err = workspace.Root(cwd); err != nil {
			return "", "", err
		}
	}
	return root, workspace.Name(root), nil

cmd/hypercube/main.go, start(), planned

		if len(s.Agents) == 0 {
			s.NoGit = !repo
			o := cfg.Orchestrator
			s.Agents = append(s.Agents, store.Agent{
				ID: store.NewID(), Name: "orchestrator", Role: store.Orchestrator,

repo is the result of workspace.IsRepo(root), a new helper that runs git rev-parse --is-inside-work-tree. start() reads the orchestrator's branch only when repo is true.

The field uses omitempty. Existing state files do not contain it, so they load with NoGit false and stay in Git mode. An empty orchestrator branch cannot mark the mode, because git branch --show-current also prints nothing on a detached HEAD in a Git checkout.

Creating a worker with dir

workspace.Resolve(base, dir) turns the dir argument into an absolute path. base is the orchestrator's directory.

  • A path that starts with ~/ is joined to the home directory.
  • A relative path is joined to base.
  • An absolute path is used as given.

The result must be an existing directory, or create_agent returns an error and the state file is not changed. The path is not limited to the home directory, and it is not compared with other agents' directories. Two workers given the same directory work in the same checkout, and the orchestrator's SessionStart text states this.

If the launch fails, the existing rollback still removes the agent from the state file. In a Git workspace, createAgent ignores a dir argument, the same as any other argument the tool does not define.

Removing workers

removeAgent calls workspace.RemoveWorktree only when NoGit is false. The rest of the function closes the pane and deletes the agent from the state file, as it does today.

down() builds its list of workers to check and remove in one loop. The plan adds NoGit to that loop's skip condition, so in a no_git workspace the list is empty and down() goes straight to killing the session and deleting the state file.

cmd/hypercube/main.go, down(), planned

	for _, a := range s.Agents {
		if a.Role != store.Worker || s.NoGit {
			continue
		}
		workers = append(workers, a)
		if err := workspace.Removable(root, a.Dir, a.Branch); err != nil {
			problems = append(problems, fmt.Sprintf("%s: %v", a.Name, err))
		}
	}

Codex trust

The Codex launch command passes a projects override that marks a directory as trusted. Today that directory comes from workspace.MainRoot(a.Dir), which returns an error outside Git. The plan uses the agent's directory as given and calls MainRoot only when that directory is in a Git checkout. The check is per agent because, in a no_git workspace, the orchestrator's directory is outside Git while a worker's directory is usually inside one.

internal/harness/harness.go, Command(), planned

	case "codex":
		// Codex keys folder trust on the main checkout, which covers worktrees. A
		// directory outside Git is trusted as it is.
		root := a.Dir
		if workspace.IsRepo(a.Dir) {
			if root, err = workspace.MainRoot(a.Dir); err != nil {
				return nil, nil, err
			}
		}

Claude Code needs no launch change. Each directory a worker runs in must already be trusted in Claude Code, or that worker's pane shows the trust dialog, as the orchestrator's pane does today for a new checkout.

SessionStart facts

facts in internal/hook/hook.go builds the text each agent receives at SessionStart. When NoGit is set, it writes a second version of that text.

  • The working directory line and the team lines leave out the branch.
  • The tool lines describe create_agent(name, dir, ...) and a remove_agent that leaves the directory in place.
  • The orchestrator is told that its directory is not a Git checkout, that it should tell each worker how to handle branches and commits, and that workers given the same directory share one checkout.
  • A worker is told that Hypercube created no branch or worktree for it and that it should handle branches and commits as the orchestrator tells it.

The text in Git workspaces is not changed.
