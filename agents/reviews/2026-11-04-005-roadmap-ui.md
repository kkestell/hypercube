## F1. Switching to source loses scroll tracking

Medium · Correctness · Fixed · `internal/ui/web/files/file-view.tsx:62`

Browser preview mode previously returned a different DOM element for
`ref={view}` from source mode. `useScrollMemory` attaches its scroll listener
once and retained the original element. After Show Source, source scrolling
was no longer recorded. Remounting the view, including when splitting a pane,
restored the old position instead of the user's current position.

### Evidence

A temporary Bun behavior test mounted an SVG preview in an open file tab,
switched through `setSource`, scrolled the new `.file-view` to 500, dispatched
its scroll event, and unmounted the view. The saved position was 0 rather than
500. The test also confirmed that mode switching replaced the scroll element.
The ownership mismatch is visible in
`internal/ui/web/editor/use-scroll-memory.ts:16` through its cleanup.

### Fix

The same scroller now stays mounted for both modes, with native content or
source rendered inside it. Find mounts only for searchable content. The new
behavior regression verifies that source scrolling after a mode switch saves
position 500 and restores it after remount.

## F2. Source encoding rejection prevents native previews

Medium · Correctness · Fixed · `internal/ui/files.go:173`

HTML and SVG files within the text limit previously had to pass `readText`
before `/file` returned their preview metadata. Valid UTF-16 documents contain
zero bytes, so the text reader returned `errBinary` and the route responded
with 415. The UI showed the unsupported text message instead of the native
browser viewer. Optional source extraction incorrectly controlled whether the
preview was available.

### Evidence

A temporary Go overlay test created a small HTML document encoded as UTF-16LE
with its byte order mark, added an isolated workspace and session, and sent a
GET to `/file`. Expected metadata status 200; actual status was 415 with
`file is binary or uses an unsupported text encoding`. The overlay added no
file to the checkout. The failure follows directly through `readText`'s zero
byte test and `fileError` at line 175.

### Fix

Optional HTML/SVG source extraction now treats `errBinary` as unavailable
source and returns preview metadata with null text. Real I/O errors and regular
text-file rejection retain their existing behavior. The HTTP regression covers
a BOM-marked UTF-16 document, including metadata, raw bytes, conditional reads,
and range requests.
