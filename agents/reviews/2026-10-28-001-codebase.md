# Codebase review: bugs, performance, and simplification

## Scope and coverage

The whole codebase at `a1fdda2`: `src/`, `src/bin/`, `src/harness/opencode.js`,
and `tests/`. Fourteen fresh reviewers on non-Claude models (GPT Sol at high
and extra high effort, DeepSeek V4.1 Flash, GLM-5.3-Flash, MiMo-V2.6-Pro, and
MiniMax-M3.1-Flash) covered it in four rounds, each with its own area and
lens:

- Round 1: the terminal layer (`mux.rs`, `runtime.rs`, `pty.rs`); host and
  session lifecycle (`host.rs`, `client.rs`, `link.rs`, `control.rs`,
  `main.rs`); messaging and state (`store.rs`, `hook.rs`, `wait.rs`,
  `mcp.rs`, `harness.rs`, the OpenCode plugin); duplication across `src/`.
- Round 2: performance of the render path and frequent processes;
  simplification of `host.rs`, `mcp.rs`, and `control.rs`; correctness of
  `workspace.rs`, `config.rs`, `main.rs`, `bar.rs`, `overlay.rs`,
  `statusline.rs`, `help.rs`, and `colors.rs`; the tests and test programs.
- Round 3: the documented contract in `docs/` against the code;
  simplification of `mux.rs` and `runtime.rs`; error handling and partial
  effects of multi-step operations.
- Round 4: end-to-end flows across modules: switching workspaces, a worker's
  life from `create_agent` to `remove_agent`, resizing while zoomed or in the
  overlay and reattaching, and `make reinstall` with queued messages.

Every finding below was checked against the code, and most were reproduced.
Reported issues that need unlikely conditions were left out: two cold starts
of one workspace at the same instant, SIGHUP-ignoring children of a harness
the host gave up on, the Kitty associated-text flag (no harness enables it),
panes with different reverse-video or grapheme-clustering modes (no harness
sets them differently), `~//` in a path, and stale test directories after pid
reuse. The documented-contract review and the end-to-end review found
nothing beyond the findings here.

Gaps:

- No harness was smoke-tested. The OpenCode plugin change (F3) was checked
  against the `subscribe` API in the installed OpenCode 2.2.0 binary and with
  `node --check`, not with a live OpenCode agent.
- The performance findings were measured by a reviewer with a benchmark
  outside the repository; the fixes were not benchmarked again.

## F1. Esc in the overlay waits for the next refresh

Medium · Correctness · Fixed · `src/runtime.rs:215`

While the overlay, the help, or the bar's path prompt captures keys, a lone
Esc is held for `INPUT_HOLD_MS` (25 ms) to tell it from the start of an
escape sequence. When the hold expired, `Runtime::wait` called
`mux.flush_input()`, which queued `Notice::Key(Esc)`, but the loop went on to
poll without taking notices again. The host saw the key only when something
else woke the loop, usually the one-second bar refresh, so closing the
overlay or the prompt with Esc lagged by up to a second when the agents were
quiet.

### Evidence

A `Runtime` on a socket pair with keys captured, given a lone Esc and a
300 ms deadline, returned `[Key([27]), Deadline]` after 301 ms instead of
about 25 ms. Notices were taken at `src/runtime.rs:179`, before
`flush_input` at `src/runtime.rs:215`.

### Fix

`wait` routes expired held input before it takes notices. The new test
`a_captured_lone_esc_is_reported_when_its_hold_ends` in `tests/live.rs`
fails without the fix and passes with it.

## F2. Caps Lock disables the prefix key

Medium · Correctness · Fixed · `src/mux.rs:2124`

Under the Kitty keyboard protocol, which Hypercube mirrors from the focused
pane and Claude Code turns on, the modifier field also carries Caps Lock
and Num Lock. `special_route` took Ctrl-b only when the modifiers were
exactly 5, and the key after the prefix, the scroll keys, and Shift-PageUp
compared the same field exactly. With Caps Lock on, the terminal sends
Ctrl-b as `CSI 98;69u`, so it went to the harness, and every Hypercube
shortcut stopped working until Caps Lock was off.

### Evidence

Ctrl-b then `1`, encoded by libghostty-vt's key encoder under
`DISAMBIGUATE`, gave `Workspace(1)` with no locks and no notice with Caps
Lock or Num Lock. Ghostty's encoder tests
(`vendor/ghostty/src/input/key_encode.zig:1619`) report Caps Lock as
modifier 65.

### Fix

`csi_key` clears the Caps Lock and Num Lock bits, so every caller compares
the modifiers that matter. The new test
`the_lock_modifiers_leave_the_prefix_key_working` fails without the fix.

## F3. One failure ends OpenCode's wake loop for good

Medium · Error handling · Fixed · `src/harness/opencode.js:84`

The plugin's turn-end loop ran `for await` over `ctx.event.subscribe`
inside a `void` async function with nothing caught. If the stream failed, or
`hook("Stop")` or `ctx.session.prompt` rejected, the loop ended silently.
From then on the agent's turns ended without `hook Stop`, so it stayed busy,
and no waiter started, so it was never woken and its messages were never
delivered until its harness restarted.

OpenCode documents the stream as "Volatile by contract: a slow consumer
overflows and fails the stream". The plugin subscribed to every event,
including streaming deltas, and when a stop was blocked, which happens
whenever messages arrive during a turn, it awaited `ctx.session.prompt`
inside the loop and stopped consuming events while the next turn ran.

### Evidence

The contract string and `subscribe`'s `types` query ("When omitted, all
events are sent") are in the installed OpenCode 2.2.0 binary, and its plugin
context passes `types` through. The blocking stop is `src/hook.rs:114`.

### Fix

The loop subscribes to the three turn-end types only, starts the turn of a
blocked stop without waiting for it, catches each event's failure, and
subscribes again a second after the stream ends.

## F4. An agent that cannot run stays busy and queues messages

Medium · Correctness · Fixed · `src/host.rs:1345`

Messages reach an agent only through its hooks during a turn or through
`hypercube wait` when it is idle. Each relaunch marked the agent busy before
starting its harness, and when the host gave up, after three quick exits or
a harness that failed to start, nothing changed it back. A worker created
with a profile whose harness exits at once reached this state:
`create_agent` reported success, the pane showed "exited 3", and from then
on `send_message` answered "Message queued", `list_agents` showed the worker
busy, and nothing was delivered. The orchestrator cannot see the pane label,
so it waited for a worker that would never answer.

### Evidence

`wait::check` (`src/wait.rs:77`) delivers only to an idle agent, and no
writer of the activity ran after the host gave up.

### Fix

Kyle chose to mark the agent exited. When the host gives up on an agent, or
a worker fails to launch, `Host::give_up` sets its activity to the new
`store::EXITED`. `list_agents` shows `exited`, and `send_message` still
queues the message but says the agent is not running and gets it only when
the session starts again; the next start marks it idle or busy as before.
`an_agent_that_keeps_exiting_is_left_exited` now waits for `exited` instead
of sleeping and checks both tools. `docs/architecture.md` describes it.

## F5. A workspace whose checkout is gone cannot be stopped or deleted

Medium · Correctness · Fixed · `src/main.rs:59`

After a checkout was moved or deleted, `hypercube status` kept listing its
workspace, but `hypercube stop <old>` and `delete <old>` failed at once with
"No such file or directory", because `workspace_at` resolved the directory
before looking for the state. `delete --all` also failed for it when it had
a worker with a worktree, because `remove_worktree` ran
`git worktree prune` in the missing checkout. The state stayed until it was
removed by hand.

### Evidence

Reproduced with states on a renamed checkout: `stop` and `delete` by the old
path failed, and `delete --all` failed with `git worktree prune: No such
file or directory`.

### Fix

Kyle delegated this decision. `stop` and `delete` fall back to the
workspace whose checkout was at the given path, when that path no longer
exists and its state file does (`existing_workspace_at`, using the new
`workspace::spelled`). `delete` skips removing worktrees and branches when
the checkout is gone, since they lived in it, and removes the workspace's
files. The new test
`a_moved_checkout_can_be_stopped_and_deleted_by_its_old_path` covers it, and
`docs/architecture.md` says so.

## F6. A workspace started before `git init` stays without Git

Medium · Correctness · Fixed · `src/host.rs:731`

`prepare` set `no_git` only when it created the orchestrator. Starting
Hypercube in a new, empty project directory and then running `git init`
there, which the orchestrator itself may do, left `no_git` set for good:
`create_agent` without `dir` failed with "this workspace is not a Git
checkout", the tool schema kept requiring `dir`, and the orchestrator's
session-start text described workers without worktrees. Only `delete`,
which loses the team, cleared it.

### Fix

`prepare` sets `no_git` on every start, as it sets the orchestrator's
branch. The new test `a_directory_that_became_a_checkout_has_git_on_restart`
covers it.

## F7. A directory outside Git gets a workspace per spelling

Low · Correctness · Fixed · `src/workspace.rs:71`

`resolve` cleaned a path lexically and kept its spelling. In Git,
`git rev-parse --show-toplevel` returns the physical path, but outside Git
`locate` returned the spelling it was given. `hypercube` run in a shell sees
the physical path, while Ctrl-b c or `hypercube start` with a path through a
symlink, such as `/tmp` on macOS, named a second workspace, with its own
host and team, for the same directory.

### Fix

`resolve` returns the canonical path. `resolve_directories` gained a
symlink case.

## F8. `.worktreeinclude` paths that Git quotes fail worker creation

Low · Correctness · Fixed · `src/workspace.rs:273`

`copy_included` read `git ls-files` and `git check-ignore` output as lines.
With Git's default `core.quotePath`, a path with a non-ASCII character comes
back quoted, as `"caf\303\251"`, and `cp` was given that literal name. The
copy failed inside `add_worktree`, which removed the new worktree and
branch, so `create_agent` failed with only the `cp` error.

### Fix

Both commands run with `-z`, and the listing is split on NUL. The set-up
test now includes an ignored `café`; it fails without the fix.

## F9. A failed `git worktree add` leaves the worker's branch

Low · Error handling · Fixed · `src/workspace.rs:242`

`add_worktree` cleaned up after `set_up` failed but not after
`git worktree add -b` failed, and Git creates the branch before it checks
out. A failing checkout, such as a non-empty `.hypercube/<name>` left from
an earlier attempt or a smudge filter whose program is missing, left
`hypercube/<name>` behind, and every retry with that name failed with "a
branch named 'hypercube/<name>' already exists".

### Evidence

Reproduced with Git: with a non-empty `.hypercube/w1`,
`git worktree add -b hypercube/w1 .hypercube/w1 HEAD` fails and leaves the
branch.

### Fix

When `git worktree add` fails, `add_worktree` deletes the branch if it did
not exist before; a branch that existed is kept, as
`create_agent_that_cannot_make_the_worktree_keeps_an_existing_branch`
requires. The new test `failed_checkout_removes_the_new_branch` covers it.

## F10. Every captured row reallocates its buffers

Low · Performance · Fixed · `src/mux.rs:365`

`Frame::capture` built each changed row in a new `RowBuf`, grew its cell
and text vectors from empty, and dropped the row it replaced. With five
panes in a 300×80 terminal each scrolling a line per frame, that was about
1,850 allocations and 3.9 MB allocated per frame.

### Evidence

Measured by the performance reviewer with a release benchmark. Reusing the
vectors cut that workload to 32 allocations and 58 KB per frame, with the
same bytes emitted.

### Fix

Both capture paths clear and refill the slot's `RowBuf`, keeping its
capacity. The new test `captures_reuse_each_rows_cell_and_text_storage`
checks both paths keep their storage.

## F11. Hidden panes are captured every frame and thrown away

Low · Performance · Fixed · `src/mux.rs:1429`

A pane hidden by zoom or by the overlay keeps its size and an empty
rectangle. Its output still made `needs_render` true, and each frame
captured its changed rows only for `Frame::draw` to skip them: about 0.3 ms
and 1.9 MB allocated per frame with four hidden workers, to emit 42 bytes.

### Fix

`needs_render` and `Mux::render` skip panes with an empty rectangle. Their
terminals are still fed, and `set_layout` repaints a pane when it is shown
again. New tests check that a hidden pane's output waits until it is shown
and that a pane held while hidden shows its last complete frame.

## F12. The signal pipe is written three times

Low · Simplicity · Fixed · `src/winch.rs:28`, `src/client.rs:223`, `src/host.rs:504`

`winch::install`, `client::catch_hangup`, and `host::catch_signals` each
made a close-on-exec pipe, stored its write end, and installed a handler
whose body wrote one byte while saving `errno`, byte for byte the same.
`host::pipe` made a fourth pipe.

### Fix

`src/winch.rs` became `src/signals.rs`, with `pipe`, `catch`, `wake`, and
the SIGWINCH pipe. The client, the host, and the live tests use it.
`AGENTS.md`, `src/lib.rs`, and `docs/architecture.md` name the new module.

## F13. The lock-file loop is written twice

Low · Simplicity · Fixed · `src/store.rs:130`, `src/host.rs:93`

`store::lock` and `host::try_lock` both opened the lock file, locked it, and
compared the held file with the path, looping when `delete` had unlinked
it. They differed only in waiting or not.

### Fix

`store::lock_file(path, wait)` holds the loop and `at_path`; `store::lock`
and `host::try_lock` call it. The unlinked-lock test moved to `store.rs`.

## F14. The client waits for a new host in two loops

Low · Simplicity · Fixed · `src/client.rs:60`, `src/client.rs:282`

`Tty::connect` and `client::start` both spawned `hypercube host` and polled
every 50 ms with the same errors and bookkeeping; only the probe differed.

### Fix

`reach_host` holds the loop and takes the probe.

## F15. `runtime::Event` copies every `mux::Notice`

Low · Simplicity · Fixed · `src/runtime.rs:28`

`runtime::Event` declared the twelve variants of `mux::Notice` again and
converted one to the other arm by arm.

### Fix

`Event::Notice(Notice)` replaces the twelve variants, and the host matches
the notices directly.

## F16. `mcp::tools` builds the worker tools twice

Low · Simplicity · Fixed · `src/mcp.rs:57`

The two arms of `tools`' `if no_git` each built `create_agent` and
`remove_agent` in full, differing only in two descriptions and the required
fields.

### Fix

The arms choose those three values, and each tool is built once. The schema
tests pass unchanged.

## F17. The orchestrator's directory is found twice

Low · Simplicity · Fixed · `src/bar.rs:259`

`bar::running` looked up the orchestrator's directory inline, as
`store::Workspace::root` did.

### Fix

`State::root` holds the lookup, and both use it.

## F18. Small helpers are copied: UTF-8 paths, cell pixels

Low · Simplicity · Fixed · `src/harness.rs:152`, `src/workspace.rs:14`, `src/mcp.rs:375`, `src/host.rs:719`, `src/mux.rs:570`

A path's UTF-8 text with the error "is not valid UTF-8" was written four
times, and a cell's size in pixels three times in `mux.rs`.

### Fix

`workspace::utf8` and `mux::cell_pixels` replace the copies.

## F19. `zoom_layout` repeats `layout`'s lone-pane rectangle

Low · Simplicity · Fixed · `src/host.rs:188`

`zoom_layout` rebuilt and checked the rectangle `layout` gives a single
pane.

### Fix

It takes the zoomed pane's rectangle from `layout(size, &[zoomed])`.

## F20. `Host::handle` has an arm that cannot run

Low · Simplicity · Fixed · `src/host.rs:1268`

`read_client` handled `Stop` and `Attach` itself, so `handle`'s
`Stop | Attach => Ok(())` arm never ran, and would have answered success if
the dispatch were reordered.

### Fix

`read_client` handles `Launch` and `Close` directly through a small `reply`
helper, and `handle` is gone.

## F21. Terminal helpers are copied across the test suites

Low · Simplicity · Fixed · `tests/integration.rs:47`, `tests/live.rs:28`, `tests/roundtrip.rs:28`

`host_replies`, `contains`, the render-state walk behind `screen`, and an
8×16 `winsize` were copied between `integration.rs`, `live.rs`, and
`roundtrip.rs`.

### Fix

They live in `tests/support/terminal.rs`. `holds.rs` keeps its own
`winsize`, whose cell size varies.

## F22. The test programs copy `raw_mode` and keep an unused command

Low · Simplicity · Fixed · `src/bin/hypercube-test-child.rs:13`, `src/bin/hypercube-test-harness.rs:252`

`raw_mode` was identical in both test programs, and the harness's `exit-at`
command was documented and implemented but never sent.

### Fix

`pty::raw_mode` is shared, and `exit-at` is removed.

## F23. Round-trip fixture tests name fixtures by position

Low · Testing · Fixed · `tests/roundtrip.rs:232`

Fifty-six hand-written wrappers tied each test name to an index into
`fixtures::ALL`, so inserting a fixture would have left later tests passing
under names of other fixtures.

### Fix

A macro generates the same tests, each looking its fixture up by name, and a
test checks that every fixture has one.

## F24. The closing-the-terminal test never closes the terminal

Low · Testing · Fixed · `tests/integration.rs:1615`

`closing_the_terminal_leaves_the_team_running` sent the client SIGTERM and
closed the pty only after it died, so it never exercised the client noticing
its terminal go away.

### Fix

The test closes the pty while the client runs, requires the client to exit
on its own with status 0, and checks that the host and agents run on.

## F25. A live test waits a fixed 100 ms for the reader

Low · Testing · Fixed · `tests/live.rs:410`

`Host::restore_terminal` slept 100 ms and pumped once before
`input_modes_are_mirrored_and_restored` asserted the modes were off, which a
loaded parallel test run can outlast.

### Fix

It pumps until the restore bytes have arrived, with a deadline.

## Verdict

The code is in good shape: no high-severity problems turned up. Six medium
findings were real problems a user could hit. Two were input bugs (F1, F2).
Two left agents unable to receive messages without any visible sign (F3,
F4). Two left workspaces in states no command could fix (F5, F6). All six
are fixed and tested, except F3, which needs a live OpenCode check. The
nineteen low findings remove duplicated code and test fragility, with
behavior preserved.
