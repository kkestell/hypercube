## F1. Git diagnostics enter the filename list

Medium · Correctness · Fixed · `internal/workspace/workspace.go:37`

Moving `check-ignore` to `gitWith` changed its output from stdout alone to
combined stdout and stderr. `copyIncluded` interprets every returned line as a
path. A successful Git command can write diagnostics to stderr, so a valid
worktree setup can fail while trying to copy a diagnostic as a file.

### Evidence

An isolated repository used a `core.fsmonitor` hook that printed
`diagnostic-from-fsmonitor` to stderr while returning a valid token.
`check-ignore --stdin` succeeded and printed `.env` on stdout. Before the fix,
`AddWorktree` failed with `copying diagnostic-from-fsmonitor: cp: ... No such
file or directory`.

### Fix

As the lead requested, `gitWith` captures stderr separately, returns stdout
alone on success, and includes stderr only in errors. A regression test uses
the fsmonitor hook with the real Git command and verifies the returned path.

## F2. Missing-directory test stops before directory validation

Low · Testing · Fixed · `internal/mcp/mcp_test.go:289`

The missing-directory case used a runtime with no live lead. `AddWorker`
returned "the session is not running" before reaching `workspace.Resolve`.
The test therefore passed even without directory validation.

### Fix

Moved this case into a focused test that starts a stand-in lead, calls
`create_agent` through the MCP transport, checks the missing-directory error,
and verifies that no worker was added.

## F3. Setup executes dependent writes before checking errors

Low · Readability · Fixed · `internal/mcp/mcp_test.go:331`

`TestSessionBoundaries` built a slice of six errors from database writes and
then ranged over it. All writes ran before the first error was inspected,
including writes that depended on earlier writes succeeding. This obscured
the setup's execution and failure order.

### Fix

Replaced the error slice with direct sequential checks, returning immediately
when a setup write fails.

## F4. Integration split loses two deletion assertions

Low · Testing · Fixed · `cmd/hypercube/integration_test.go:399`

The split removed the checks that refusing deletion of a running session
with a dirty worker leaves its plugins running, and that deleting the last
session preserves its workspace. The remaining dirty-session deletion test
seeds stopped agents; other deletion tests did not inspect the workspace
after its last session was deleted.

### Fix

The lead selected these two checks for restoration inside
`TestDeletingASessionLeavesOthers`. The test now checks the refused response,
session and agent state, original processes, and absence of shutdown commands
before cleaning the dirty file and retrying. After deleting the remaining
session, it verifies that the snapshot still contains the empty workspace.
