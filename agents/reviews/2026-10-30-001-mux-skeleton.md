## F1. ANSI colors ignore the outer terminal's theme

Medium · Correctness · Fixed · `mux/internal/server/attach.go:230`

`drawFrame` built SGR from `RenderCellStyle`, whose colors libghostty resolves to RGB through Ghostty's built-in palette. Every palette color a program writes, such as red from SGR 31 in a prompt, `ls`, or `git`, reached the outer terminal as a fixed true color. Attached panes showed Ghostty's default colors instead of the user's theme, while default foreground and background did follow the theme.

### Evidence

A probe pane printing `\033[31mRED` drew `\x1b[0;38;2;204;102;102;49mRED` in the attach frame.

### Fix

The lead chose to keep palette colors as palette colors. `drawFrame` now reads the cell's `Style`. `appendSGR` writes palette entries 0 to 7 as 30–37 or 40–47, entries 8 to 15 as 90–97 or 100–107, the rest as `38;5;n` or `48;5;n`, and RGB colors as `38;2` or `48;2`. A comment notes that a palette changed with OSC 4 is not shown. Repeated styles are still skipped, by comparing the SGR bytes. `TestAttachKeepsPaletteColors` checks that SGR 31 arrives as 31. The plan's drawing note now matches.

## F2. The libghostty stamp cannot be built by name

Low · Readability · Fixed · `mux/Makefile:23`

The stamp target was the absolute path `$(CURDIR)/build/ghostty-vt/.built`, so `make build/ghostty-vt/.built` in `mux/` reported no rule. `build`, `test`, and `check` were unaffected.

### Fix

The target is now the relative `$(STAMP)`, `build/ghostty-vt/.built`. The install prefix and `PKG_CONFIG_PATH` stay absolute. `make -q build/ghostty-vt/.built` now reports it up to date.
