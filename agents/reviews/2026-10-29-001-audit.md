# Codebase audit: bugs, performance, duplication, and complexity

## Scope and coverage

`src/` and `src/harness/opencode.js` at `e9fc670`. Six reviewers on GPT Sol at
high effort each covered one area:

- The terminal layer: `mux.rs`.
- The host: `host.rs`.
- Messaging and state: `mcp.rs`, `hook.rs`, `wait.rs`, `store.rs`.
- Transport: `client.rs`, `link.rs`, `runtime.rs`, `pty.rs`, `signals.rs`,
  `control.rs`, `main.rs`, `recording.rs`.
- Setup: `workspace.rs`, `harness.rs`, the OpenCode plugin, `config.rs`,
  `schedule.rs`, `statusline.rs`.
- The UI: `bar.rs`, `overlay.rs`, `teamlist.rs`, `splash.rs`, `tesseract.rs`,
  `colors.rs`, `help.rs`, `icons.rs`.

Each finding was checked against the code. Reported issues that need unlikely
conditions were left out: workspace names with multi-codepoint emoji
misaligning the bar's hit boxes, a symlink followed by `..` in a worker
directory, and an OpenCode `default_agent` other than Build (Kyle's
configuration sets none). No reviewer found incidental complexity worth
changing.

Gaps: the findings were verified by reading the code, not by running it. The
Claude Code hook behavior in A1 and A2 rests on the official hooks reference.

## A1. A Claude Code subagent takes its parent's messages

Medium · Correctness · Open · `src/hook.rs:16`, `src/hook.rs:97`

Claude Code runs settings-level hooks inside its native subagents, and the
hook input carries `agent_id` to tell them apart. `hook::Input` reads only
`session_id`, so a subagent's PostToolUse takes the messages queued for the
Hypercube agent. When an orchestrator runs an Explore subagent while a worker
reports, the report goes into the subagent's context, and the orchestrator
never sees it.

### Fix

Read `agent_id` and skip delivery for PostToolUse events that carry one, as
the OpenCode plugin does for child sessions. Add a hook test whose input has an
`agent_id` and whose queue stays untouched.

## A2. An interrupted Claude Code turn leaves the agent busy

Medium · Correctness · Open · `src/hook.rs:105`, `src/wait.rs:80`

Claude Code runs no Stop hook when Kyle presses Esc during a turn. The agent
stays busy in the state file, and its waiter delivers only to idle agents, so
messages sent to it wait until Kyle types a prompt. A failed turn is covered by
StopFailure (`37fa65b`); an interrupted one is not.

### Fix

Mark the agent idle on a signal Claude Code gives after an interruption, such
as the `idle_prompt` Notification hook, and start a waiter there.

## A3. Tasks with workers do not fire on a host never attached

Medium · Correctness · Open · `src/host.rs:852`, `src/schedule.rs:160`

`ready` marks every saved worker busy because its launch will send `NUDGE`,
but agents launch only on the first attach. `schedule::fire` skips a task whose
team has a busy agent, so a task with workers does not fire until a client
attaches, and missed minutes are not made up. `make reinstall` starts every
workspace again without attaching, so this follows each reinstall.

### Fix

Leave unlaunched agents' activity as saved and set the launch activity when the
harness is spawned, as `relaunch` does.

## A4. A collapsed worker keeps the focus

Medium · Correctness · Open · `src/mux.rs:862`, `src/host.rs:1367`

`Pane::focusable` ignores `collapsed`, and collapsing a pane does not move the
focus. After Kyle collapses the focused worker, keys go to the hidden pane, its
cursor can be drawn over the pane below it, and Ctrl-b o can select it.

### Fix

Exclude collapsed panes from focus, move the focus off a pane when it
collapses, and show a cursor only in a pane with rows and columns.

## A5. Pane hyperlinks are dropped

Medium · Correctness · Open · `src/mux.rs:2585`, `src/mux.rs:2663`

Captured cells keep text and style but not hyperlinks, and the renderer never
writes OSC 8. Links that harnesses print, such as Claude Code's file links,
reach the host terminal as plain text. The round-trip fixture with a hyperlink
passes because the screen snapshots do not compare links.

### Fix

Capture each linked cell's URI with `GridRef::hyperlink_uri`, write OSC 8
around linked runs, and close an open link at each pane edge. Compare links in
the round-trip snapshots.

## A6. Removing workers during a label drag can panic the host

Low · Correctness · Open · `src/host.rs:1406`

`Drag::Label` keeps a position in the viewed team's panes. When workers close
while the mouse button is held, the next motion indexes `viewed` past its end
in the `expanded` closure, and the host and every agent in it end.

### Fix

Store the dragged pane's `PaneId` and look up its position on each motion,
ending the drag when the pane is gone.

## A7. Keys typed during the startup terminal query are lost

Low · Correctness · Open · `src/client.rs:457`

`query` keeps every byte read while it waits for the terminal's replies, for up
to a second, and only the replies are used. Keys typed in that window, or read
together with the last reply, are dropped.

### Fix

Separate the replies from the rest of the input and pass the rest on to the
splash or the host in order.

## A8. The dirty-worktree check follows Git's display settings

Low · Correctness · Open · `src/workspace.rs:393`

`dirty` runs `git status --porcelain`, which honors `status.showUntrackedFiles`
and submodule `ignore` settings. With either set, `removable` passes a worktree
with untracked files or submodule changes, and `worktree remove --force`
deletes them.

### Fix

Run `git status --porcelain --untracked-files=all --ignore-submodules=none`.

## A9. Changed rows take the per-cell stale-row path

Low · Performance · Open · `src/mux.rs:380`, `src/mux.rs:663`

Each output read marks the cursor's row stale for the combining-character
workaround, and `capture` reads stale rows cell by cell through the terminal
grid even when Ghostty has also marked them dirty. Streaming output takes the
slow path on most frames.

### Fix

Read dirty rows through the render-state iterator, and use the stale-row path
only for rows Ghostty reports clean.

## A10. `Link::send` copies every frame twice

Low · Performance · Open · `src/link.rs:209`

`send` encodes each message into a new vector and copies that into the queue.
A frame over 1 MiB is first split into a `Vec<Message>` of copied chunks.

### Fix

Append each header and payload slice to the queue directly, and iterate an
oversized frame's chunks without collecting them.

## A11. The width helpers copy the rest of the string per cluster

Low · Performance · Open · `src/host.rs:528`, `src/host.rs:598`

`text_width` and its sibling pass the whole remaining slice to
`unicode::grapheme_width` for each cluster, and the binding copies that slice
into a new `Vec<u32>` each time. Measuring an N-character string copies
N(N+1)/2 code points. The chrome, the bar, and the lists measure on every
redraw.

### Fix

Bound the slice passed to `grapheme_width`, or convert the text to code points
once and measure through the FFI directly.

## A12. Every waiter parses the state file four times a second

Low · Performance · Open · `src/wait.rs:57`

Each `hypercube wait` loads and deserializes the whole state file every
250 ms, whether or not it changed. Ten idle agents parse it forty times a
second for as long as they are idle.

### Fix

Compare the file's inode, size, and modification time before loading it, and
keep the locked check before delivery.

## A13. Partial pty writes shift the whole pending input

Low · Performance · Open · `src/mux.rs:303`

`write_input` drains the front of the input `Vec` after each partial write,
moving everything after it. A large paste into a busy harness is copied once
per partial write.

### Fix

Keep an offset into the pending input and clear the buffer when it empties.

## A14. The new-team prompt reloads the state on every key

Low · Performance · Open · `src/host.rs:1929`

`teamlist_key` calls `read_teamlist` after every `Action::Move`, so each typed
character or selection move loads the state file, though only the list's own
fields changed.

### Fix

Invalidate the chrome for `Action::Move` and reload only after creating or
deleting a team.

## A15. The notification scanner duplicates a libghostty-vt callback

Low · Simplicity · Open · `src/mux.rs:655`, `src/mux.rs:2434`

`Notifications` parses every output byte for OSC 9 and OSC 777 before Ghostty
parses the same bytes. The pinned libghostty-vt provides
`Terminal::on_desktop_notification` for both.

### Fix

Register the callback beside the bell and title callbacks, write the
notification to the host from it within the existing size and side-output
limits, and remove `Notifications` and `OscState`. Check that the callback
leaves OSC 9;4 progress reports out.

## A16. The workspace and team prompts each implement the same editor

Low · Simplicity · Open · `src/bar.rs:108`, `src/teamlist.rs:143`

`Bar::key` and the prompt branch of `TeamList::key` both handle Enter, Esc,
Backspace, UTF-8 validation, and control characters.

### Fix

Share one function that edits a string and returns whether it changed, was
submitted, or was cancelled, and keep each prompt's actions in its owner.

## Verdict

Five medium findings affect normal use: lost messages to orchestrators running
Claude Code subagents (A1), agents left busy after an interrupt (A2), tasks
that do not fire after a reinstall (A3), keys going to a collapsed pane (A4),
and missing hyperlinks (A5). The rest are low-severity correctness edges,
per-frame and per-poll costs, and two duplications.
